# 原版《赤壁》指令机制与素材

> 对象：`_work/iso/CB.EXE`（PE32/x86，SHA-256 `2db7cc102e6fde547ab05d77cfddabc2079f5bc9be9b6b59b17bf435c5798cb7`）
> 资源：`BMP/BMP.LWC`（图标）、`SET/INTERFAC.EXP`（指令/图标注册表）、`SET/PROMPT.EXT`+`PROMPT.EDX`（名称表）
> 方法：REA（Ghidra provider）静态分析 + LWC/EXP 解码；**未运行原版**。
> 范围：指令面板、图标、热键、提示、派发/入队/模式分派的机制与素材；不重新推导玩法数值。
> 说明：`plan.md` 的“禁止新增逆向分析”约束针对玩法规则取证；本目录是用户 2026-10-27 明确指定的指令表现层/机制专项。

## 结论摘要

1. 原版的指令 UI 是**注册表驱动**的：`INTERFAC.EXP` 里有 **117 条** `帧号 999 999 指令ID` 记录（`999/999` = 只注册、不固定摆位）。其中**面板指令 17 条**（`16130–16146`），另有取消 `16025`；核心注册项共 18 条。
2. 核心指令面板是 **3×3 九格**；工人/战斗两套模板共用格位，第 3–5、9 格按队伍类型替换（见 §3）。9 个热键固定为 **Q/W/E/A/S/D/Z/X/C**。
   但“3×3 九格”只适用于**成组部队/武将本体**；**未编组单位只有 4 项**（移动/组建/加入/上船），**工人成员 3 项**（移动/解散/上船），**战斗成员 4 项**（移动/组建/加入/上船），运输船 1–2 项，多选 3–4 项——见 §5A。
3. 指令图标在 `BMP.LWC` 的 **154–169** 帧；每帧 **40×120 = 3 个 40×40 状态**（normal / pressed / hover），注册表另有一张 `170`（取消）。子菜单图标是 57–153 帧。
4. 悬停/按下/抬起分别是三种视觉状态：鼠标移入 → 行 2（悬停）；按下 → 行 1（按下）；抬起命中 → 发命令并回到行 0。`禁用`（状态 3）的源矩形落在 3 行图之外，实际表现为不绘制/空槽（见 §9 的限制）。
5. 点击/热键最终都走同一条路：`PostMessage(WM_COMMAND, 指令ID)` → `FUN_00428a50` 组装参数 → `FUN_0042a8a0` 把 8 dword 命令块写进本势力 **64 槽任务表** → 每帧泵到单位 → `FUN_0045b4e0` 按模式分派。
6. 面板切换/置灰由 `FUN_0040d9c0(panelID, ..., mask)` 完成：先把面板的 **15 个按钮槽**全置状态 3，再按位启用掩码对应的槽；核心 3×3 只用前 9 槽，建造/生产菜单可用到 15 槽（掩码可到 `0xFFFF`）。
7. 提示文字是 `(热键) 名称`，名称来自 `PROMPT.EXT` 的 23–40 项；绘制在屏幕底部 `y=0x1cc (460)`。

## 1. 数据格式

### 1.1 指令/图标注册表 `INTERFAC.EXP`

文件用 **XOR 0x22** 解码后是文本。注册表条目语法：

```text
<BMP.LWC 帧号>  999  999  <指令 ID>
```

`999 999` 表示该指令只登记图标与 ID，不参与固定界面矩形摆放。共 **117 条**，分类如下：

| 类别 | 数量 | 指令范围 | 图标帧 |
|---|---:|---|---|
| 核心指令 | 18 | 16025, 16130–16146 | 170, 154–169 |
| 阵法 | 10 | 16190–16199 | 113–122 |
| 翻页 | 2 | 16200/16201 | 124/123 |
| 计谋 | 9 | 16210–16218 | 98–106 |
| 建造菜单 | 32 | 16150–16187 | 57–89 |
| 生产/研究 | 44 | 16028–16126 | 90–153 等 |
| 其他 | 2 | 0（特殊按钮） | 227/228 |

> 帧号与指令 ID 的对应关系以 `data/registry.json` 为准；本轮没有把建造/生产条目的名称逐条对齐（见 §9）。

### 1.3 图标 `BMP.LWC`

- 绝大多数指令图标是 **40×120**：3 行 × 40×40（normal / pressed / hover）。
- `57 / 73 / 89` 是 **40×40** 单状态（73/89 推断为建造列表里的“民居”条目，57 对应特殊项 16028）。
- `121` 是 40×121（多 1 行像素，按 3 行使用）。
- 图标本身带红色槽边框，不需要额外按钮底图。
- 预览统一用 `RES/SCORE.PAL`（“Main Palette”）；实机战场调色板未截屏确认。

## 3. 按钮对象与状态

### 3.1 按钮字段（`FUN_00403900` 及相关）

| 偏移 | 含义 |
|---:|---|
| `+0x64` | 名称字符串（PROMPT 文本） |
| `+0x164` | 帧宽（40） |
| `+0x168` | 帧高（40） |
| `+0x16c` | 源图基准 x |
| `+0x170` | 源图基准 y |
| `+0x174` | 方向判定：等于帧宽 → 状态纵向排布，否则横向 |
| `+0x17c…0x188` | 当前源矩形（left/top/right/bottom） |
| `+0x18c / +0x190` | 屏幕 x / y |
| `+0x194` | **指令 ID**（PostMessage 的 wParam） |
| `+0x198` | 状态：0 正常、1 按下、2 悬停、3 禁用、4 隐藏 |
| `+0x19c` | 上一状态 |

状态切换 `FUN_00403900(button, state)` 会把源矩形设为：

```
纵向排布：top = baseY + state * 40, left = baseX
横向排布：left = baseX + state * 40, top = baseY
```

所以 40×120 图正好覆盖状态 0/1/2；状态 3 落在图外，绘制时被裁掉（见 §9）。

### 3.2 鼠标/热键状态

- **悬停/移动** `FUN_004042b0(x,y)`：进入按钮 → 状态 2，并调用 `FUN_00403cb0` 显示提示；移出按钮 → 状态回 0（按下后移出也会取消）。
- **按下** `FUN_00404080(x,y)`：遍历当前面板的按钮（`DAT_00487460`；核心面板为前 9 个），命中且非 3/4 → 状态 1，播放 `Effect\Click.wav`。
- **抬起命中** `FUN_00404200(x,y)`：状态回 0，调用 `FUN_00403f40` 发命令。
- **热键按下** `FUN_0040de80(key)`：把 Q/W/E/A/S/D/Z/X/C 映射到 `DAT_00482a24[0..8]`（与鼠标使用的 `DAT_00487460` 是同一组 9 个槽），状态 1 并立即发命令。
- **热键抬起** `FUN_0040e080`：状态回 0。
- 数字键 0–9 另有 `FUN_0040e1f0` 的编队/选择路径，不属于指令面板。

### 3.3 提示

`FUN_00403cb0(button)`：

- 在 `DAT_00482a24[0..8]` 中查找按钮的槽位 → 得到热键字母；
- 把 `(Q) 名称` 写进临时缓冲；
- `FUN_00419b90(..., y=0x1cc)` 画在屏幕底部（y=460）。

## 4. 从点击到执行

```text
鼠标移动  FUN_004042b0 ──▶ 状态 2（悬停） + 提示
鼠标按下  FUN_00404080 ──▶ 状态 1（按下） + Click.wav
鼠标抬起  FUN_00404200 ──▶ 状态 0 + FUN_00403f40
                                     │
热键      FUN_0040de80 ──────────────┤
                                     ▼
              PostMessage(hwnd, WM_COMMAND=0x111, wParam=指令ID)
                                     │
                                     ▼
              FUN_00428a50  指令处理器（0x3f02–0x3f12 / 菜单 ID）
                                     │ 写 DAT_004b7efc（模式）、DAT_004b7f00/04/08…（目标）
                                     ▼
              FUN_0042a8a0  组装 8 dword 命令块
                                     │ 每个选中单位一份
                                     ▼
              势力任务表 DAT_004b4e50 + faction*0x208（dword 单位；64 槽 × 8 dword）
                                     │ 满槽 → “CTRL_TASK Warning … Task List is full”
                                     ▼
              FUN_0042ae10 → FUN_0042add0  每帧泵到单位排队块
                                     ▼
              FUN_0045b4e0  按模式分派
```

要点：

- **命令块 8 dword**：`DAT_004b7ef0` 起，整块拷贝进任务表。

- **移动目标**：模式 2 且目标为队长/编队时，每个单位目标 = 点击格 + 自己的阵法偏移。
- **任务表满**：每个势力 64 槽，`DAT_00483410[faction]` 是环形游标；满时输出 `CTRL_TASK Warning 1/2 — Task List is full` 并跳过该单位。

## 5. 面板切换、置灰与子菜单

`FUN_0040d9c0(panelID, param2, mask)`：

1. 旧面板的 **15 个按钮槽**全部置状态 3（禁用）；
2. `DAT_00482a24 = 新面板的按钮数组`（最多 15 项）；
3. 按 `mask` 的第 0..14 位（共 15 槽），把对应按钮置状态 0（启用）；
4. 用 `FUN_00455f40` 重新摆位/绘制（同样遍历 15 槽）。

> 核心指令面板只用前 **9** 槽（3×3），热键/提示也只查 `DAT_00482a24[0..8]`；建造/生产菜单会用满 15 槽。

掩码示例（`FUN_00426e40`，按单位类型选生产/建筑面板）：

- 类型 6/7 → 面板 `0x11620`，掩码 `1 → 3 → 7`（科技等级递增解锁）；
- 类型 8/9 → 面板 `0x116e8`，掩码 `1 → 3 → 5`；
- 类型 0xC/0xD → 面板 `0x115bc`，掩码 `1 → 3 → 7 → 0xF`；
- 类型 0xE/0xF → 面板 `0x11684`，掩码 `1 → 3 → 7 → 0xF`；
- 类型 0x14 → 面板 `0x1174c`，掩码可到 `0x20/0x40/0x60`；
- 类型 0x17 → 面板 `71000`，掩码 `0xFFFF`。

子菜单：

- 工人建造菜单：指令 `16139` → 面板 `0x111de`；
- 建筑侧建造/生产：指令 `16140` → 面板 `0x11210`；
- 翻页/重开：`0x3f37/0x3f38/0x3f48/0x3f49` → `0x11210/0x1121a/0x11242/0x1124c`；
- 阵法 `16190–16199`、计谋 `16210–16218` 通过 `0x42a8a0` 走模式 10/5；
- 取消 `16025` 根据当前模式置 `0x16/0x17/0x18`。

## 5A. 选择对象 → 面板（工人/士兵/武将/运输船）

这是本轮补充的重点：**同一个 3×3 面板并不总是 9 格**。原版先按“选中对象”的分类选一个面板 ID，再用掩码启用槽位。

### 5A.1 选择分类与面板 ID（`FUN_004275E0`）

| 选择状态 | 代码判定 | 面板 ID | 槽数 / 掩码 |
|---|---|---|---|
| 无选择 | — | `0x11171` | 0 |
| 单个武将 · **带工人**（category 12） | `FUN_00424F30` = true | `0x111D4`（或 `0x11206`，`DAT_004b8cb8 != 0`） | **8** / `0xFFFF`（第 9 格空） |
| 单个武将 · **带士兵**（category 9/13 或其它） | `FUN_00424F30` = false | `0x11238` | **9** / `0xFFFF` |
| **单个工人成员**（有将、选中成员，category 10） | `local_354` | `0x11300` | **3** / `0x07`（有载货时 `|0x0F` 第 4 槽） |
| **单个战斗成员**（有将、选中成员） | `local_358` / `local_34C` | `0x1129C` | **4** / `0x0F` |
| **未编组单位**（`+0x150 == 0xFFFF`） | `local_35C` | `0x1129C` | **4** / `0x0F`（有载货时 `|0x10` 第 5 槽） |
| 多选 · **工人队/工人成员**（有将 + category 10） | `local_354` | `0x11300` | **3** / `0x07`（有载货时 `|0x0F` 第 4 槽） |

| 建筑 | 选中建筑 | `0x11210` / `0x111DE` | 建造/生产菜单 |
| 其它/敌人 | — | `0x11171` 或信息面板 | — |

> “单个武将”指**选中将本体**（category 9/12/13）；此时面板由**该武将带的队伍类型**决定：category 12 = 工人队，9/13 = 战斗队。  
> **点将本体和点成员是两套面板**：点将本体 → 8/9 项完整面板；点同一队的工人/士兵成员 → `0x11300`/`0x1129C` 的 3–4 项受限面板。  
> “多选”时也不显示完整 8/9 项，而是 3–4 项受限面板；`local_354`/`local_358`/`local_34C`/`local_35C` 是选择循环里的分类计数器。

### 5A.2 工人：有武将与无武将

| 状态 | 判定 | 行动 | 图标帧 |
|---|---|---|---|
| **未编组工人（无将）** | `+0x150 == 0xFFFF`、category 10 | **移动 16130、组建 16144、加入 16145、上船 16142** | 154、167、168、165 |
| **工人成员（有将，点成员）** | category 10、`+0x150 != 0xFFFF` | **移动 16130、解散 16136、上船 16142**（载货时 +返回 16146） | 154、160、165（+169） |
| **工人队（有将，点将本体）** | category 12，`FUN_00424F30` true | 移动、攻击、运输、建造、修理、休息、解散、上船 | 154、155、162、163、164、158、160、165 |
| **武将带工人** | 将本体 category 12 | 同上 8 项（第 9 格空） | 同上 |

关键差异：

- 未编组工人 **没有** 攻击、运输、建造、修理、休息、解散；只有“组建/加入”把工人并成队伍。
- **工人成员**（有将但点的是成员）只有 **移动/解散/上船**；运输/建造/修理/攻击/休息都在**将本体**的 8 项面板上。这是“同一个工人队，点将和点成员看到不同面板”的关键。
- 成组后才会出现工人专属的 **运输（162）/建造（163）/修理（164）**；同时出现攻击（155）、休息（158）、解散（160）。
- **组建动作本身决定后续面板**（`FUN_0045D810` → `FUN_00442E40`）：
  - 选中的是工程队（category 10）→ 新队伍 category **12**（工人队）。
  - 其它单位 → category **9** 或 **13**（战斗队，取决于 `FUN_00425020` 的 7/13 分支）。

## 10. 对重制版的直接含义

- 指令面板应按“**注册表 + 面板模板 + 掩码**”实现，而不是把 18 条指令硬编码成 9 个按钮。
- **面板先看选中对象，再看队伍类型**：
  - 未编组单位 → 4 项（移动/组建/加入/上船）；
  - 工人成员（有将、点成员）→ 3 项（移动/解散/上船）；
  - 工人队/带工武将（点将本体）→ 8 项（工人面板）；
  - 战斗成员（有将、点成员）→ 4 项（移动/组建/加入/上船，后两项是否可用待核对）；
  - 战斗队/带兵武将（点将本体）→ 9 项（战斗面板）；
  - 运输船 → 1–2 项（移动/下船）；
  - 多选 → 3–4 项受限面板。
- **点将本体和点成员必须分开实现**；否则会把“工人成员只有移动/解散/上船”误做成完整工人 8 项。

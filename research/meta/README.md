# 原版《赤壁》秘籍与启用方式

> 本文按“**秘籍/作弊模式**”理解（你写的“密集”应当是“秘籍”的输入笔误）。  
> 唯一依据：`CB.EXE` 原始二进制 + REA/Ghidra 静态分析。历史秘籍文章只用于对照，不作为原版事实。  
> 目标 EXE：SHA-256 `2db7cc102e6fde547ab05d77cfddabc2079f5bc9be9b6b59b17bf435c5798cb7`。

## 0. 结论摘要

1. **开启方式**：游戏画面按 **Enter** 打开信息输入条，输入 **`eternal`**（小写最稳），再按 **Enter**；代码在输入到第 5 个字符 **`n`** 时已经翻转秘籍 flag，所以 `etern` 也能触发。再次输入可关闭。
2. **秘籍 flag**：`DAT_00484BEC`。F2–F9 的作弊分支都先检查它是否为 1。
3. **F2–F11 功能**：F2 自动/托管、F3 武将降级、F4 武将升级、F5 界面/指针开关（待实机确认）、F6 取消建造前置、F7 无敌、F8 地图全开、F9 四项资源各 +10000、F10 无动作、F11 截图。
4. **两个常见误传**：
   - F7 代码是**当前 side 免疫伤害**，不是旧文章写的“建造/行进加速”。
   - F9 代码是每项 **+10000**（`0x2710`），不是 +1000。
5. F11、P 等隐藏键不检查秘籍 flag；`[` / `]` 的选关分支在秘籍 flag 下才进入。

## 1. 启用流程（代码级）

### 1.1 Enter 信息输入条

- Enter 的虚拟键码是 `0x0D`；键分发表把它送到 `0x4544D1`。
- 该分支调用 `FUN_0040E3E0(1)`，并切换 `DAT_00482A10`（信息输入条状态）。
- 信息输入条打开后，键盘事件仍进入同一键处理流程；Esc（`0x1B`）走 `0x454562` 关闭。

### 1.2 输入 `eternal`

代码位置：

```text
字符串 "eternal"：VA 0x484BF8
输入索引：      DAT_00484BF0
秘籍 flag：     DAT_00484BEC
比较循环：      0x454823–0x45485C
```

伪代码：

```c
edx = DAT_00484BF0;
cl = key_char;
if (eternal[edx] == cl) {
    DAT_00484BF0++;
    if (DAT_00484BF0 == 5) {
        DAT_00484BEC = 1 - DAT_00484BEC;  // toggle
    }
} else {
    DAT_00484BF0 = 0;
}
```

关键细节：

- 比较是**逐字符**的，字符串是小写 `eternal`；
- 只检查到 **第 5 个字符**（`etern`）就翻转 flag；
- 完整输入 `eternal` 时，`a`、`l` 继续匹配字符串后两位，不会撤销；
- 如果中途打错，索引归零，需要从头输入；
- 因此“必须输入完整 7 个字母”不是代码要求，**前 5 个字符已经生效**。

> 历史文章写“Enter → Eternal → Enter”；代码大小写比较未做显式大小写转换，建议使用**英文小写** `eternal`。

## 2. 秘籍键与效果

键分发表在 `0x454FEC`，入口 `0x4544B3`。以下 `VK` 是 Windows 虚拟键码。

| 键 | VK | 代码入口 | 效果 | 是否检查 flag |
|---|---:|---|---|---|
| F2 | `0x71` | `0x454571` | 切换 `DAT_00485318`：自动进行游戏/小兵自动；主更新 `FUN_0045AFE0` 分支使用 | 是 |
| F3 | `0x72` | `0x454593` | 选中武将等级 −1（最低 0），`FUN_0042B190(0)` | 是 |
| F4 | `0x73` | `0x4545AF` | 选中武将等级 +1（最高 9），`FUN_0042B190(1)` | 是 |
| F5 | `0x74` | `0x4545CB` | 翻转 `DAT_00483190` / `DAT_00484C00`，调用 `FUN_00402840` 重置光标矩形；界面/指针开关（具体画面待确认） | 是 |
| F6 | `0x75` | `0x45460B` | 翻转 `DAT_00483424`；`FUN_00428810` 建造菜单掩码全开，`FUN_00428A50` 绕过建造前置/位置失败分支 | 是 |
| F7 | `0x76` | `0x45462D` | 翻转 `DAT_00483428`；`FUN_0041FE90/FUN_0041FEE0` 中当前 side 受击伤害强制 0（无敌） | 是 |
| F8 | `0x77` | `0x45464F` | 翻转 `DAT_004850C8`；地图可见性/全开，`FUN_00459A00` + `FUN_00441AC0` | 是 |
| F9 | `0x78` | `0x454676` | 当前 side 金/粮/木/铁各 **+0x2710 = 10000**，可重复累加 | 是 |
| F10 | `0x79` | `0x454F9A` | 直接返回，无动作 | 否 |
| F11 | `0x7A` | `0x454713` | 调用 `FUN_0041ACA0` 截图，写 BMP 到游戏目录；不检查 flag | 否 |

补充：

- F3/F4 都是对**当前选中的第一个武将**（`DAT_004B76F4` → `FUN_00424F10` 判武将）操作；没有选中武将时函数直接返回。
- F3/F4 改的是武将等级字节 `DAT_004AE144[officer]`，并调用 `FUN_00426420` 刷新官职/面板；不会补发经验。
- F2 的 `DAT_00485318` 会进入存档/读档块；秘籍 flag `DAT_00484BEC` 不在本轮看到的存档块列表中，可能是单局状态。
- F6 的代码确认“取消前置/失败分支”，但具体建造入口是否仍扣资源要按入口分别验证；不要直接把它叫“免费建造”。
- F7 与部分旧文章冲突：静态代码只看到 `DAT_00483428` 在伤害函数里把当前 side 的伤害置 0；没有速度/建造加速路径。
- F9 与部分旧文章冲突：`0x2710` 是 10000，不是 1000。

## 5. 版本与限制

- 本分析针对上述 SHA-256 的 `CB.EXE`；标准版/增强版或其他改版可能不同。
- “F5 界面/指针”只确认了 `DAT_00483190`/`DAT_00484C00` 与光标矩形刷新；具体画面效果需要原版实机逐帧确认。
- “F6 免费建造”没有直接证据；当前只确认菜单/前置失败分支被绕过。
- `DAT_00484BEC` 是否是单局状态，需要进一步核对其是否进入存档；目前未在已查看的存档块列表中看到。
- 秘籍功能会改变运行时状态；本文不修改游戏代码，也不提供自动执行脚本。

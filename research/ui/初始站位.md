# 原版《赤壁》开局初始站位

> 目标版本：`CB.EXE` SHA-256 `2db7cc102e6fde547ab05d77cfddabc2079f5bc9be9b6b59b17bf435c5798cb7`。  
> 地图对象来自原版 `MEDS/*.MED` 的转换数据；本文的“锚点”是地图对象里的格坐标，不等于运行时最终可见格。  
> 本文只讨论**开局站位**；敌军 AI 的进攻节拍、等待门槛、目标选择见 `research/ai/README.md`。

## 0. 结论

- 每关第一个参战方是玩家，地图 `objects[]` 里同一 `tail[0]` 的部队属于同一武将。
- `tail[0]` 的**首支部队位置**是武将生成锚点；武将本体是**另外生成**的，不占地图对象，也不计入“成员数”。
- 单位不能重叠。武将生成锚点若已被首成员占据，原版会通过 `FUN_00442970` → `FUN_0045AC40` 搜索附近可通行空格，因此**武将最终可见格可能不同于锚点**。
- **`chibil1`（二吕进犯）**：地图对象只有 4 个工人成员，没有第 5 个“主将对象”。四名工人的锚点是 `(15,184)、(15,185)、(16,186)、(16,187)`；徐庶生成锚点是 `(15,184)`，与工人 1 同锚点。玩家实际看到的“主将 +(1,1) 到 (1,4) 的四名工人”是运行时让位后的最终相对布局。
- 因此：**研究数据中的 `leader`/`heroBody` 只能当作生成锚点；UI 不能把它直接当成最终站位，也不能让主将与首个工人重叠。**
- `research/ai/data/levels.json` 保存了 34 关的逐组锚点和逐成员相对偏移；本文第 3 节给出各关的编组锚点汇总。

## 1. chibil1：主将与四名工人

### 1.1 地图对象中的四名工人

`chibil1` 的玩家方为 P2。四名工人都属于徐庶（tail=43），在地图对象表中的绝对位置是：

| 工人 | 地图格 `(A,B)` | 地图像素 `(px,py)` | 相对首成员锚点 |
|---|---:|---:|---:|
| 工人 1 | **(15,184)** | (646,1997) | (0,0) |
| 工人 2 | **(15,185)** | (668,2008) | (0,+1) |
| 工人 3 | **(16,186)** | (690,2019) | (+1,+2) |
| 工人 4 | **(16,187)** | (712,2030) | (+1,+3) |

坐标方向按地图对象/渲染公式理解：A 增大向屏幕右，B 增大向屏幕下；四个锚点在屏幕上本身就连成一条斜线。

### 1.2 主将徐庶的位置

- 徐庶的**生成锚点**是 `(15,184)`，即工人 1 的锚点。
- 地图对象表中没有徐庶本体；他是按 `tail=43` 的首成员位置另外生成的。
- 因为不能重叠，徐庶不能和工人 1 最终都在 `(15,184)`；原版会搜索附近空格，所以**最终主将格要以运行时为准**。

### 1.3 玩家实际看到的线形

玩家实际观察到的相对布局可以概括为：

| 单位 | 相对主将 `(A,B)` | 说明 |
|---|---:|---|
| 主将徐庶 | **(0,0)** | 最终可见的主将格 |
| 工人 1 | **(+1,+1)** |  |
| 工人 2 | **(+1,+2)** |  |
| 工人 3 | **(+1,+3)** |  |
| 工人 4 | **(+1,+4)** |  |

这是**运行时让位后的相对位置**，不是上面四个地图对象锚点的直接复制。

若主将最终绝对格为 `(X,Y)`，则四名工人的绝对格是：

```text
(X+1, Y+1)
(X+1, Y+2)
(X+1, Y+3)
(X+1, Y+4)
```

例如：**如果**主将最终格仍是 `(15,184)`，则工人为 `(16,185)、(16,186)、(16,187)、(16,188)`。但主将的实际最终格由开局空格检索决定，不能把 `(15,184)` 无条件当成最终主将格。

## 2. 原版生成/让位逻辑

关键路径：

1. 地图对象加载时，同一 `tail[0]` 的部队都归入该武将。
2. 武将生成时，使用首成员的位置作为锚点；`FUN_0045D810` 取首成员坐标并调用 `FUN_00442E40`。
3. `FUN_00442E40` → `FUN_00442970` 创建武将本体所在单位。
4. `FUN_00442970` 在需要落位时调用 `FUN_0045AC40`：
   - 先检查原坐标是否可用；
   - 若被占用，则按原版偏移表搜索附近的合法空位。
5. 因此武将本体最终会被放到附近的空格，地图对象锚点只表示生成起点。

这说明“主将与首成员同锚点”和“最终不重叠”并不矛盾：**同锚点是生成输入，不是最终占格**。

- **`chibic6` 襄阳招降**：我方没有编组战斗单位，只有 5 名未编组工人；见 `playerUnassignedUnits`。

## 4. UI 落位建议

1. **区分字段**：
   - `anchor` / `leader`：地图对象或首成员生成锚点；
   - `finalCell`：运行时实际占格。
2. 渲染开局时，如果主将与首成员同锚点，必须执行一次空格搜索/占格解冲突；不能直接把两个精灵画在同一格。
3. 若 UI 只需要显示“原始地图对象”，可以标注为“锚点”；若要显示玩家实际看到的开局站位，应使用运行时最终格或第 1.3 节观察到的线形。
4. 不要把 `leader` 同时当作“地图对象里第五个主将对象”；主将本体是额外的武将实体。

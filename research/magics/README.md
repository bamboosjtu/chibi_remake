> 目标：`CB.EXE` SHA-256 `2db7cc102e6fde547ab05d77cfddabc2079f5bc9be9b6b59b17bf435c5798cb7`。  
> 仅以原版二进制 + REA/Ghidra 静态分析为准；`docs/` 和重制实现只作为差异对照，不作为原版证据。

## 1. 计时、目标与费用

### 1.1 800 tick 是确认值

- `FUN_00443550(unit+0xC, status, value)`：
  - 状态 flag 写在 `unit+0x60+status`；
  - 对应计时器 `unit+0x48+2*status` 清零。
- `FUN_0045B4E0` 在每个单位更新末尾：
  - 对每个 flag=1 的状态，计时器 +1；
  - 当 `timer > 799`（即第 800 次更新）时清除该状态。
- 因此 800 是**单位更新次数**，不是固定秒数。按主循环间隔换算：

| 主循环间隔 | 800 状态更新时间 | 100 火场更新时间 |
|---:|---:|---:|
| 20 ms | ≈16 s | ≈2 s |
| 30 ms | ≈24 s | ≈3 s |
| 50 ms | ≈40 s | ≈5 s |
| 100 ms | ≈80 s | ≈10 s |

> 主循环为 `FUN_00454280 → FUN_0045AFE0`（逻辑）→ `FUN_0041F040`（特效更新）。  
> 状态计时在单位分派 `FUN_0045B4E0` 中；火场在 `FUN_0041F040 → FUN_00444AC0 → FUN_00453060` 中。

### 1.2 目标模型

`FUN_0045F8B0` 取点击目标后：

```text
FUN_00424980(1, target, list, 15)
```

- 收集**目标所属队伍成员**，最多 **15** 支；
- 不是“以点击点为中心 2 格内”；
- 激励/加速/减速/远视/混乱/滚木/埋伏对目标队伍所有成员施加状态；
- **恢复**只对目标队伍主将；
- **火攻**是地面格，不按队伍。

### 1.3 费用与解锁

命令 16210–16218，费用表 `DAT_00485328`：

```text
50 / 100 / 100 / 100 / 200 / 100 / 100 / 10 / 100
```

解锁掩码：

| 武将等级 | 可用数 | 掩码 | 新增计谋 |
|---|---:|---|---|
| 0 | 0 | `0x000` | 无 |
| 1 | 1 | `0x001` | 激励 |
| 2 | 3 | `0x181` | 恢复、火攻 |
| 3 | 4 | `0x1C1` | 埋伏 |
| 4 | 5 | `0x1C9` | 远视 |
| 5 | 7 | `0x1CF` | 加速、减速 |
| 6 | 8 | `0x1EF` | 滚木 |
| 7–9 | 9 | `0x1FF` | 混乱 |

订正依据：同哈希 `CB.EXE` 的 `FUN_004289A0`（`0x4289AF–0x428A22`）按武将等级索引上述十项表。此前记录的 `7/63/255/511` 实际来自 `FUN_004288C0` 的阵法表，不能用于计谋。此处为本地 Capstone 对原始文件的只读反汇编核对，不是新取得的 REA Evidence。

计谋掩码直接对应命令 `16210–16218`，显示格位固定为三列三行：激励/加速/减速，远视/混乱/滚木，埋伏/恢复/火攻。未解锁格留空，不将已解锁图标压到前面。`FUN_00455ED0` 给出三列、40 像素步距（x=501+40×列，y=336+40×行），与用户提供的低等级截图一致。子菜单没有返回条；点击战场退出。

谋略池：初值 10，上限 `2×智力 + 15`。

## 2. 重点：火攻

### 2.1 调用与 effect

`FUN_0045F8B0` case 9：

```c
FUN_00453A80(click_x, click_y, 100, 4, 1);
```

`FUN_00453A80` 生成 **effect type 7**（火场），字段含义：

| 字段 | 值 | 含义 |
|---|---:|---|
| 位置 | `click_x/click_y` | 点击的地面格 |
| `+0x28` 伤害 | **10** | 每次命中直接扣 10 HP |
| `+0x64` 间隔 | **4** | 每 4 次更新判定一次 |
| `+0x6E` 寿命 | **100** | 100 次更新后结束 |
| 范围 | 单格 | 没有 AOE；`FUN_00453D10` 只取该格单位 |

火场更新见 `FUN_00453060` case 7：

```c
timer++;
if (timer_before >= 4) { timer = 0; damage = FUN_00453D10(effect); }
...
if (counter >= 100) end;
```

### 2.2 伤害时序（重要）

计时器初值为 0，判定发生在自增之前：

- 第 1–4 次更新：`0..3 >= 4` 为假，不伤害；
- 第 **5** 次更新：`4 >= 4`，第一次命中；
- 之后每 4 次：第 9、13、…、97 次；
- 第 100 次更新计入寿命上限，火场结束。

所以：

- **伤害间隔 4 更新**；
- **首次命中在第 5 次更新**；
- 100 更新窗口内是 **24 次命中**，不是 25 次；
- 最大 **24 × 10 = 240 HP**；
- 理论上表有 25 个“4 的倍数”时隙，但首个时隙在第 0 次更新时未结算，因此实际少一次。

### 2.3 伤害属性

- **固定 10 HP**，不走普通攻击/防御公式；
- **不检查阵营**，可以烧友军；
- **不检查建筑/单位类别** 的额外减伤（仅走通用的 `+0x78` 守卫）；
- 目标离开格子后不会再被打；重新进入会再次被判定；
- 伤害是“格上单位”，不是格子范围伤害；
- 火场结束时 `FUN_00453EF0` 可能把 `tile < 4` 的地形改为焦土变体 `tile+8`，不影响伤害数值。

### 2.4 不是文档里的 20 DPS × 6 秒

`docs/08-abilities.md` 写“1.5 格内 20 伤害/秒 × 6 秒”，与代码不符：

- 单格，不是 1.5 格 AOE；
- 每 4 更新 10 HP，不是每秒 20；
- 持续时间是 100 更新，随游戏速度变化，不是固定 6 秒；
- 实际最大 240 HP，不是 120。

## 3. 加速 / 减速：精确倍率

### 3.1 移动

`FUN_0045B910` 用 `iVar13` 控制子格步进：

| 状态 | `iVar13` | 实际移动 |
|---|---:|---|
| 普通 | 1 | 每单位更新 1 步 |
| 加速（状态2） | 2 | 每单位更新 **2 步 = ×2** |
| 减速（状态3） | 0 | 只在**奇数单位更新**推进 1 步 = **×0.5** |

关键代码：

```c
iVar13 = 1;                       // 普通
if (status2) iVar13 = 2;          // 加速
if (status3) iVar13 = 0;          // 减速
if (iVar13 == 0 && (unit_tick & 1) == 0) return;  // 偶数更新不走
if (iVar13 == 2) step *= 2;       // 加速双步
```

- 加速 **×2**，不是旧文档的 ×1.5；
- 减速 **×0.5**；
- 状态2/3 互斥：施加一个会清除另一个；
- 部分特殊单位（`FUN_004250A0` 为真的船/运输类）原本基准就是 2 步，加速不会再额外叠加；普通地面单位按上表。

### 3.2 攻击速率

`FUN_0045D440` / `FUN_0045DD90`：

```c
rate = DAT_004AF58F[type];   // 每类型基础攻击 rate
if (status2) rate *= 2;
else if (status3) rate >>= 1;
period = floor(1000 / rate);
```

- 加速：**rate ×2**，攻击周期约减半；
- 减速：**rate >>1**，攻击周期约加倍；
- 因为 `>>1` 会截断，奇数 rate 时减速不是严格 ×0.5 的周期；
- **只确认攻击/动作的两支函数**；没有在修理函数中看到状态2/3读取，不能直接说“修理也 ×2/÷2”。旧文档的修理倍率仍需另找证据。

### 3.3 持续时间

状态2/3 持续 **800 次单位更新**；重复施放会重置对应计时器，不叠加。

## 4. 远视：固定 10 格覆盖

`FUN_00426280`：

```c
if (*(char *)(unit + 0x64) == 1)  // 状态4（远视）
    return 10;
return DATA.EXP 的 v5 视野;
```

- 状态4 生效时有效视野 **直接返回 10**；
- 不是 `基础视野 + 10`，而是**覆盖**；
- 基础视野 5/7 的单位都变成 10；
- 作用对象是目标队伍成员（最多 15）；
- 持续 800 次单位更新；
- 到期时先按 10 格移除可见性，再按基础视野重新标记；
- 视野刷新：`FUN_004583E0` / `FUN_00457E60`，最终 `FUN_00441940` 标记所属方可见。

所以“远视 10 格”这个旧说法在数值上正确，但必须理解为**覆盖为 10**，不是 +10。

## 5. 其余计谋

### 5.1 激励

- 状态1；对目标队伍成员施加；
- 每 **100 个全局更新**（`DAT_00485320 % 100 == 0`）调用 `FUN_0045B410`；
- 对处于状态1的武将：谋略 **+5**；
- 上限 `2×智力 + 15`；
- **没有直接士气 +15**；旧文档的“士气+15”不成立；
- 状态持续 800 次单位更新。

补充：非激励状态时，同一每 100 tick 流程会让武将当前 HP **+10**（封顶），这是通用回复，不是激励的士气效果。

### 5.2 混乱

`FUN_0045F8B0` case 5：

1. 给目标队伍所有成员写状态5；
2. 对每个成员向阵营任务队列追加一个 **0x1B** 任务；
3. `FUN_0045FFF0`（0x1B 动作）只在状态5缺失时结束；
4. 状态5存在时该任务一直空转。

关键语义：

- **不是即时硬控**：当前正在执行的任务不会被立刻打断；0x1B 是队列任务，轮到它才生效；
- 如果 0x1B 在状态5到期后才轮到，它直接完成，实际不冻结；
- 没有随机移动、没有伤害；
- 状态5持续 800 次单位更新。

### 5.3 滚木

`FUN_0045F8B0` case 7：

- 状态7，所有目标队伍成员各得到一个 **0x1C** 任务；
- `FUN_00460020` 每 **30 次更新**扫描一次；
- 扫描使用 `FUN_004247A0(2, caster, ...)`，范围 = 施法者视野（远视状态4时 10 格）；
- 取扫描列表**第一个**敌人；
- 通过 `FUN_00425570` 取其武将/主将；
- 士气字段 `+0x173` **−50**；
- **不做 HP 伤害**，也不是 2 格 AOE/40 伤害；
- 命中后清除状态7；找不到目标则每 30 更新重试，直到 800 更新上限。

每个受术成员独立执行自己的 0x1C，因此多成员队伍可能各自命中一个目标。

### 5.4 埋伏

状态6，只对两类单位产生实际战斗效果：

| 类型 | 名称 | 正常射程 | 埋伏射程（=视野） | 攻击 |
|---|---:|---:|---:|---|
| 32 | 步兵 | 1 | **5** | 特殊攻击，固定 **30** 伤害 |
| 45 | 弓兵 | 6 | **7** | 特殊攻击，固定 **30** 伤害 |

代码路径：

- `FUN_00424C70`：状态6 + 类型32/45 时，攻击距离改用 `DAT_004AF58C[type]`（视野）；
- `FUN_0045D440`：满足条件时调用 `FUN_00421050`；
- `FUN_00421050` 生成 effect type8，伤害字段 **30**；
- `FUN_00453580` 命中时直接扣 30 HP，不走普通攻击公式。

因此：

- **没有隐身/不被索敌**；状态6 不被任何可见性/索敌函数读取；
- 仅步兵/弓兵获得“视野射程 + 固定 30 伤害”的埋伏攻击；
- 其他兵种的状态6 目前只看到计时 flag，没有战斗效果；
- 持续 800 次单位更新。

### 5.5 恢复

`FUN_0045F8B0` case 8：

```c
leader->hp += 0x32;                 // +50
if (leader->hp > maxHp) leader->hp = maxHp;
```

- 只对目标队伍的**主将/武将本体**；
- 不是全队治疗；
- 即时，无状态计时；
- 费用 10。

## 6. 状态系统

| 状态 | 名称 | 设置/清除 | 持续 |
|---:|---|---|---:|
| 1 | 激励 | 计谋；不与其他状态互斥 | 800 |
| 2 | 加速 | 设置2并清3 | 800 |
| 3 | 减速 | 设置3并清2 | 800 |
| 4 | 远视 | 计谋；到期恢复基础视野 | 800 |
| 5 | 混乱 | 计谋；0x1B 空转任务 | 800 |
| 6 | 埋伏 | 计谋；仅32/45有战斗效果 | 800 |
| 7 | 滚木 | 计谋；命中后提前清除 | 800 上限 |

- 每个单位每个状态有独立计时器（`unit+0x48+2*status`）；
- 重新施加会 **timer=0**，刷新而不是叠加；
- 计时器在单位更新时分派；载员/运输等是否继续更新取决于其是否参与单位循环，不能只看全局时间；
- 清除时 `FUN_00443550` 只写 flag=0 并清 timer，不额外结算伤害。

## 10. 限制

- 800 / 火攻 / 倍率来自静态代码；未运行原版逐帧验证。
- 火攻“24 次”严格遵循 `timer` 初值 0、先判定后自增、100 次寿命的代码顺序；若实机观察到不同相位，应检查主循环是否在创建帧额外调用了一次特效更新。
- “修理是否受加速/减速影响”未找到状态读取，暂不下结论。
- 混乱的队列语义依赖 `FUN_0042AC00` 的阵营任务队列；如果实机命令队列允许覆盖，表现可能略有差异。
- 火场结束时的地形焦土化只确认 `tile<4 → +8` 的分支，具体地图表现需素材/实机核对。

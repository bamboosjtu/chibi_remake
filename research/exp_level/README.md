# 原版《赤壁》武将升级与经验获取

> 对象：`_work/iso/CB.EXE`（SHA-256 `2db7cc102e6fde547ab05d77cfddabc2079f5bc9be9b6b59b17bf435c5798cb7`）
> 数据：`SET/DATA.EXP`（品级/兵种/武将表）、`SET/BATTLE.EXP`（关卡初始等级）、`MISSION.EXT`（升级提示文本）
> 方法：REA（Ghidra provider）静态分析 + DATA.EXP 解码；**未运行原版**。
> 范围：武将等级 0–9 的经验阈值、经验来源、升级效果、品级/称号、117 名武将的逐级数值；不重新推导战斗伤害公式。

## 结论摘要

1. 武将等级 **0–9（10 级）**；升级阈值（当前等级 → 下一级）：

   `200 / 500 / 1000 / 1800 / 3000 / 5000 / 8000 / 12000 / 18000 / 27000`

   前 9 个用于 0→1 … 8→9；**27000 是 9→10 的残留值，因封顶永不消费**。从 0 级练到 9 级累计需要 **49,500 经验**。
2. 升级判定在 **击杀 / 建造完工 / 资源交付** 三个入口里重复出现：
   `if (level < 9 && xp >= threshold[level]) { xp -= threshold[level]; level += 1; }`
   **一次获得经验最多升 1 级**，溢出保留到下次；9 级后经验仍可累加但不再升级。
3. 经验来源只有四类（直接写经验字段的代码只有三处，事件另走脚本）：
   - **击杀**：击杀者所辖武将获得死者类型的“击杀经验”列；同时按“士气摆动”列调整双方士气。
   - **建造完工**：施工队所辖武将获得该建筑类型的“击杀经验”列。
   - **资源交付**：每次交付/入库 +1 经验（非工程队分支）。
   - **事件**：如“在长坂坡救回糜竺，经验增加”；具体数值由事件参数 `eventExperience` 决定，本轮未解出。
4. 升级只通过 **品级值** 影响：
   - **单挑体力** = 武力 + 品级（0–120；UI/单挑按 ×100/120 显示）↑
   - **攻A/攻B** = (品级 + 武力) × 类型攻 / 100 ↑
   - **防A/防B** = 武力 × 类型防 / 100 **不变**（公式不含品级）
   - **将本体 HP** = 类型 500，**不变**；升级不直接回血。
   - 称号按“类别 + 等级”查 29 条称号表：校尉 → 中郎将 → 偏/裨将 → … → 大将军。
5. `DATA.EXP` 的武将“等级”列是 **1 基**，装载时减 1；基础数据全部为 **0 级**。每关的初始等级由 `BATTLE.EXP` 的“档次”另行设置（档次 − 1）。
6. 117 名武将分 4 个名册：吴 33、蜀 14、魏 51、群 19；类别分布：骑 28、步 24、弓 21、文 44。基础 HP 统一为将本体 500（DATA.EXP 的 100 会被装载器覆盖）。

- 阈值表在 `FUN_00421b50`、`FUN_00422a20`、`FUN_0045c320` 中各内联一份，值完全一致。
- 经验字段在武将记录 `+0x1C`（`DAT_004ae148 + heroIndex*0x2C`），等级在 `+0x18`（`DAT_004ae144`）。

## 2. 升级算法

```text
xp += amount
if (level < 9 && xp >= threshold[level]) {
    xp -= threshold[level]
    level += 1
    if (本方单位) {
        show "我将领战斗英勇，斩获甚多，晋升一级"   // MISSION.EXT 第 13 项，ID 0x0C
        play sound 0x6A
        refresh 武将信息面板（称号/体力/攻击/经验）
    }
}
```

- **只升 1 级**：没有 `while`；大额经验会留下溢出，下次获得经验时再升。
- **升级提示**：`FUN_0041a460(0x0C)` + `FUN_0041b1a0(0x6A)`；只对玩家本方（`FUN_00425190`）播放。
- **当前 HP**：升级代码没有写将本体 HP；HP 仍为 500（受伤后按每 100 帧 +10 恢复到 500）。
- **单挑体力当前值**：升级也不直接补满；上限（武 + 品级）随等级提高。

## 3. 经验来源

| 来源 | 获得者 | 数值 | 代码/证据 |
|---|---|---|---|
| 击杀 | 击杀者所辖武将 | 死者类型的“击杀经验”列 | `FUN_00422a20`；`DAT_004af5a4[type*0x38]` |
| 建造完工 | 施工队所辖武将 | 建筑类型的“击杀经验”列 | `FUN_0045c320` |
| 资源交付 | 交付队所辖武将 | **+1 / 次**（与 200 载重无关） | `FUN_00421b50` |
| 事件 | 事件指定武将 | `eventExperience` 参数（未解出具体值） | MISSION.EXT 事件文本 / scenario_rules |

### 3.1 击杀经验

- 击杀者 = 死者的“最后攻击者”；若其有武将，则 `FUN_00425570` 找到所辖武将，经验 += 死者类型的击杀经验。
- **按类型固定值，与伤害量无关**；最后一击拿全额。
- 死者所辖武将同时按“士气摆动”列掉士气；击杀者所辖武将加同值。
- 例：击杀民居（类型 24/25）= **+40 经验、+1 士气**；击杀大旗（26）= +50、+2；击杀将本体（29/31/33/35）= +10、+3；运输船（47）= +20、+2。
- 完整 53 类（27 建筑 + 26 单位）见 `data/kill_xp.json`。

### 3.2 建造经验

- 工地完工时，施工队所辖武将获得 **该建筑类型的击杀经验**（不是造价，也不是 HP）。
- 例：帅帐 150、粮仓 15、民居 40、大旗 50、步兵所 50。
- 只在施工队/工程队路径（`FUN_00424f30` 为真）结算；与击杀同名同值，可视为“建造等同于击杀一个该建筑”。

### 3.3 交付经验

- 每次资源交付/入库，`FUN_00421b50` 在非工程队分支给所辖武将 **+1 经验**，然后查升级；同函数还负责金/粮/木/铁入库和粮满回滚。
- 与载重无关：一次运 200 也是 +1；采集节点采空不经过击杀路径，**不给击杀经验**。

### 3.4 事件经验

- 事件文本：“在长坂坡救回糜竺，经验增加。”（MISSION.EXT 事件段）
- 部分任务在 `scenario_rules.json` 中用 `experienceParameter: "eventExperience"` 标记，说明数值来自任务参数/事件脚本，而不是固定常量。
- 另一个相关事件：“斩敌将夏侯恩，夺其所配青冈剑，武力上升。”——这是永久武力提升，不是经验。
- 事件经验的具体数值本轮未解出（见 §9）。

## 9. 已知空缺

1. **事件经验的具体数值**：`eventExperience` 参数未从 BATTLE.EXP/事件脚本解出；“长坂坡救糜竺”只确认会增加经验。
2. **称号第二值**（`secondary`）只被装载，未在体力/攻防公式中使用；用途未确认（可能是备用/显示值）。
3. **防御公式**已确认不含品级；但升级是否改变其他隐藏属性（例如单挑命中/暴击）未逐一验证。
4. **计谋解锁档位**来自既有研究（等级 0–2/3–4/5/6–9），本轮未重新从代码推导。
5. **每关初始等级**由 `BATTLE.EXP` 的“档次”设置（等级 = 档次 − 1），本目录只给 0–9 的通用成长表，不逐关列出初始等级（可参考 `docs/research/OPENING-FORCES.md`）。
6. **取整**：攻防用整数除法（余数丢弃）；如果重制版用四舍五入，会在个别武将上差 1 点。

## 10. 对重制版的直接含义

- 等级用 **0–9**，阈值表按上表；一次奖励只升 1 级，溢出保留。
- 经验来源按“击杀 / 建造完工 / 交付 / 事件”实现；击杀经验按**死者类型**查表，不按伤害分摊。
- 升级只提升 **单挑体力上限** 与 **攻A/攻B**；**防A/防B 与将本体 HP 不变**，不要顺手加防或回血。
- 称号是“等级 + 类别”的显示层，29 条称号表；不要把称号做成额外属性。
- 将本体 HP 与“单挑体力”是两个概念：前者类型 500，后者武 + 品级（0–120，UI ×100/120）。

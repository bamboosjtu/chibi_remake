# 三项 P1 整改

复核输入为 `tmp/review.md`，起点为 `be602bf`。本轮覆盖 §2.1 端口层、§2.2 模拟热点、§2.3 单位状态机；原评审保留，验收及输入/源码/日志哈希另记在 `p1-remediation-acceptance.json`。

## 端口与真实依赖

删除 23 个内部适配器文件，20 个模块把 `REQUIRED_SERVICES` 放在实际调用旁边；两个无依赖模块不再创建空端口，campaign 不再通过端口调用自己。共享依赖类仅负责弱引用、装配检查和同步作用域，不转发业务方法。跨层命令、领域状态访问、原生长期回调继续使用受检适配器。

| 同口径指标 | 整改前 | 整改后 |
|---|---:|---:|
| 独立适配器文件 | 62 | 39 |
| 适配器代码行 | 5329 | 3600 |
| 含共享类及模块内契约的保守行数 | 5329 | 3650 |
| 清单识别的机械转发 | 693 | 478 |
| 显式内部接收者调用 | 未解析 | 450 |
| 同名同体辅助函数组（评审脚本） | 167 | 108 |

保守行数下降约 31.5%，机械转发实际减少 215 处。机械计数使用前后相同的清单算法；原报告约 400 的估计不作为精确分母。调用链直接写明提供者，门禁检查 acquire、守卫、提供者、方法及可解析的参数数量。它验证受限源码形式，没有声称实现完整语法树解析；其他端口的名称命中仍不能用作删除证据。

迁移核对了适配器中的附带逻辑。原 cheat attack 适配器中的取消旧命令、设置目标和进入攻击状态归回 `cheat_rules`，没有作为机械转发丢弃。新增参数数量负向用例覆盖这一类迁移错误。未增加代码生成器。

## 资源、施工队和堵塞路线

资源片缓存保存格坐标、掩码与边界源键，按导航身份、几何修订、资源修订失效；根键包含资源种类。保留点击起点的 BFS 顺序，最多缓存 16 个根，动态占用和城门权限每次判断。候选终点排序及保留位置过滤维持原顺序。一批查询只借用一次避让标志；已禁用的点不再反复写入，所有退出结果恢复原导航图。

饰物点击采用空间桶，桶内保留原数组索引顺序。缓存不保留资源对象或旧世界，资源耗尽后立即失效。施工队索引仅活在一次同步决策内，按归属和队伍查询，避免为每个空闲单位重复扫描全表。成员身份、队伍人数和施工兵种共用一个实现；不要求所有 Dictionary 写入维护长期索引。

堵塞终点每次单位更新最多尝试六条替代路线，包含普通寻路回退时最多十二次导航查询。候选顺序不变，中途保存 `blocked_cursor`，正常移动或取消命令后删除，完整邻域搜索结束才增加失败次数。这改变重试时序，故显式升为 `battle-rules-v4`，只接受登记指纹到固定目标的 `bounded-blocked-navigation-v1` 迁移。旧档缺游标从零开始；未知指纹拒绝。

`benchmark_hot_paths.mjs` 使用同一脚本串行运行历史工程和当前工程，比较 1080 格树林/八工人、600 单位施工选择、点击、堵塞终点和建造选址。保存目标及路径完全相同是硬断言；延迟、查询次数、机器信息、引擎/Harness/规则源码哈希写入证据。此微基准不替代正式包、GPU 或完整战场实时验收。

在 i7-8700、Windows、同一已审核引擎上，预热三次后采样三十次的 P95：

|---|---:|---:|
| 1080 格树林、八工人派令 | 114.766 | 31.574 |
| 饰物点击 | 0.889 | 0.041 |

堵塞场景的每次调用查询数为 96→12。它衡量分摊到单次更新的延迟，未声称完整 48 个候选的总搜索量减少；建造选址的小量级耗时也不能外推为完整战场收益。

## 单位动作

`_step_unit_inner` 从 190 行降为 18 行，移除长函数豁免。共同前置条件、跟随工作成员和各状态处理器分别实现；交付等待仍跳过动画尾处理，附着、状态效果、工地和卸载的顺序保留。新测试逐一驱动十三状态，并由现有战斗、采集、建造、科技、载员和原生对照测试补足实际动作覆盖。

## 验收与限制

必需 release 套件增加两个专项脚本；CPU 热点基准进入 hosted 源码发布工作流和本地 FullRegression。隔离缺图工程与语法检查也纳入未提交的新文件并忽略已删除的工作树文件，使开发工作区与提交后 CI 检查同一候选内容。

广泛回归保留所有原预算。并行运行有两项大型测试触及超时，800 单位微基准触及耗时阈值；原始失败日志保留，单独进程复测另记，不能用放宽预算或覆盖日志掩盖失败。800 单位隔离测量为 64.82 ms，低于原有 100 ms 预算。大型载员测试在独占运行中完成 11 张地图，耗时 185.3 秒，接近 190 秒上限；后续可按地图拆分可观察用例，不能把本次通过表述为充足的超时余量。

资源种类加入缓存键后，额外重跑受影响的采集、工人、预览、资源层与两项确定性基线。完整验收集合、复测关系和最终数值以机器证据为准。`tools/inputs/baselines.json` 不修改。

P2/P3 仍保留：BattleAccess 的其余借用、宽状态/构造协议、全部存档语义边界、发布证据硬门禁、Game/输入/启动拆分等。本轮没有声称已完成这些工作，也不把 CPU 微基准当作完整发布性能证明。

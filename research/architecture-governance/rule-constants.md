`constant_contract.gd` 校验行宽、完成状态、进度单调性、研究线覆盖、角色唯一性和容量关系；整批校验检查兵种与武将引用。Loader 独立读取结果也执行跨目录校验，拒绝返回带非法引用的可消费文档。发布边界再次守住同一契约。

BattleConfig、BattleState、main 和 BattleAccess 中的目标常量转发删除。成长阈值也改为查询已有成长目录，不再保留第二份 EXP_LEVELS 数组。TechnologyState 的完成分支改为消费科技行的 completion 定义，生命增量从科技行取得；原有结果和幂等性保留。

## 保留的语义差异

- `naval` 包含运输船与旗舰；`navalTechnology` 不包含运输船，仍包含旗舰，不能合并为同一集合。
- 武将类型判定与“携带武将记录的实体”不同；Combat.hero 继续要求非空 officer 记录。
- 实体上限统计本方存活且不在死亡淡出中的所有实体，包括建筑。生产队列预留名额；其他入口保留原有检查时点，不将六处门禁改造成另一套计数算法。
- 主将、每队成员和运输载员分别使用自己的上限。采集载重 200、研究周期 200 和 UI 尺寸等同值常量不替换为人口上限。
- 具体舰型、兵种几何和特殊技能仍保留自身规则，不把所有数字型兵种引用都解释为通用角色分类。

原生后端接受同一目录的 naval 与 transport ID，删除 C++ 内对 47 的独立运输船判定；重新构建 DLL，并同步源码签名与版本化素材摘要。构建产物以临时文件原子替换发布，避免覆盖旧测试夹具硬链接所指向的不可变二进制。

规则指纹新增覆盖三个目录，角色集合内部排序不改变身份，科技顺序和档位归属仍保留。指纹覆盖范围扩大后，旧指纹不再与当前运行规则匹配；不增加旧指纹别名或格式迁移。模拟摘要与规则身份是独立的验收项，不能用放宽存档身份来维持模拟基线。

## 门禁和证据

`tools/inputs/rule_constants_baseline.json` 保存从重构前代码提取的完整值摘要；CI 不重生成该基线。B 通道集合也从检查点代码提取后归并，名称、所有费用/效果和分类均可对照。故意调整平衡值需要显式评审基线更新。

`rule_constants_check.mjs` 检查旧常量名/转发、十进制与十六进制角色副本、人口数值门禁和原生运输船判定。负例还通过独立临时项目运行真实 CLI，确认错误能转化为非零退出码。源模式检查不宣称完整 AST 或动态调用证明，运行回归补充真实准入和计算行为。

科技费用、四档加成、大本营费用与容量摘要由三个目录生成到 `docs/05` 的标记块，门禁检查新鲜度。它们是文档投影，不是运行时的另一份定义。只运行 `--write` 更新文档不会接受行为基线变化。

`test_rule_constants` 覆盖格式和跨目录拒绝、0–60 类型的角色边界、整型成员查找、科技完成与重放、冻结对象复用、实体/主将额度、死亡与归属，以及队列预留。启动故障夹具新增跨目录非法引用，并保留首次查询前删除全部规则文件、世界交换/回滚与旧世界释放验证。原有编组生命周期测试移除对场景 EXP_LEVELS 的旧接口依赖。

实际执行结果、基线对照、源码与工具指纹见 `rule-constants-acceptance.json`。本机结果不代表尚未触发的 GitHub hosted job 或 GPU/发行 EXE 验收。

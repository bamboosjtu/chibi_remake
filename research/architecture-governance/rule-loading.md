# P2：规则启动边界与 tick I/O

本轮复核 `tmp/review.md` §2.3，处理模拟目录内的规则文件读取、惰性原生后端发现和无条件计时。§2.4 的科技、兵种角色和人口上限常量归并仍是独立工作，本轮没有修改规则数值或刷新模拟基线。

## 启动与所有权

规则加载由 `Game._init` 显式启动。Godot 在 autoload 的 `_ready` 前构造主场景对象；只在 `_ready` 加载规则会使直接启动 `main.tscn` 的世界过早创建。因此加载、校验、冻结以及原生提供者安装均在主场景构造前完成，`_ready` 再决定是否开放应用启动。

`app/rules/rule_loader.gd` 读取九个固定目录，汇总文件读取、JSON 解析和必要字段错误。失败报告不包含可消费的部分目录，初始化结果缓存，重复调用不会重试文件读取。`rule_contract.gd` 与 `scenario_contract.gd` 是纯值校验器；`rule_catalog.gd` 发布前再次守住契约，复制并递归冻结整批数据，拒绝运行中替换。目录不持有世界、服务、节点或回调。

| 目录 | 消费方式 |
|---|---|
| unit_definitions、production_units、buildings | 启动数据只读；向各世界的独立地图定义应用覆盖，费用和施工数组独立拥有 |
| officers | 每个世界创建独立武将数组与记录，再应用开局等级 |
| officer_progression | 官职、奖励和经验阈值共享冻结值；保留源奖励表的有序首项匹配语义 |
| command_variants、scenario_rules | 普通世界和候选世界引用相同冻结模型，不在构造器打开文件 |
| unit_tuning | stratagem、移动和视野查询读取同一内存对象；持续时间受 Unit Schema 上限约束 |
| native_math | 启动时验证算法和签名，供可选后端安装使用 |

原生发现与签名验证移到 `app/rules/native_backend.gd`，同样只初始化一次。缺少 DLL 使用脚本实现；存在但加载失败或不兼容则拒绝启动。`math_kernel.gd` 仅保留已安装提供者查询、测试用脚本选择和退出释放。

RulesIdentity 从已安装的八个玩法目录计算有效投影，删除保存路径对这些文件的重复读取；显式 ABI 与投影算法保持一致。原生签名和源码完整性清单继续与玩法身份分开。

## tick 与性能工具

模拟目录的十处 FileAccess 已移除。`stratagem_rules.config()` 不保留惰性加载分支，不复制目录；重复查询返回同一冻结对象。世界交换和回滚复用进程规则，世界拥有的武将、费用和施工数组可以独立修改。

墙钟采样集中到 `ProfileClock.now`，关闭开关时直接返回 0。模拟总计时使用 `timing_enabled`，细分阶段使用 `profile_enabled`；导航计时也由显式开关控制，功能计数仍保留。性能 Harness 在逻辑和实际帧测量期间主动打开计时，渲染预热时关闭，并验证模拟状态不变，防止把未采样的 0 当作测量结果。

## 门禁与回归

- 架构门禁拒绝 simulation 内的文件/目录访问、动态资源加载、JSON 解析和进程执行；脚本 preload 声明允许保留。墙钟只能经固定的 opt-in helper 采样。
- 静态负例覆盖被禁止 API、动态 load、非法计时开关及注释/字符串干扰；此检查是源模式门禁，不宣称完整语法树或动态调用关系证明。
- `test_rule_catalog` 覆盖九个目录深层冻结、必要字段拒绝、无重复发布、武将/费用/施工数组隔离、状态递减、默认关闭计时、测量开启，以及候选回滚、交换和旧世界释放。
- `test_rule_startup.mjs` 仅修改独立项目副本。成功启动后，在第一次规则系统查询前删除全部规则源文件，再运行状态和候选世界场景；另覆盖直接启动主场景、缺文件、坏 JSON、九目录结构错误、汇总错误、主场景拒绝启动、缺 DLL、DLL 损坏与原生签名不匹配；缺 DLL 用例还断言实际使用脚本后端。
- 用例已登记到 development 与 CPU CI 清单，故障探针登记为 wrapper 专属。GitHub CI 和 Windows CI 均接入故障入口；托管 CI 使用无视图模式，本地有视图用例验证附着后的回滚。

本机执行结果及源码指纹记录在 `rule-loading-acceptance.json`。完整 release/development 合计 104 项均有通过结果。运输回归首次触及原有 190 秒上限，单独重跑用时 178.6 秒通过；初次失败和重跑结果均保留，不扩大门槛。启动顺序修正后另重跑应用生命周期、规则、世界交换、性能 Harness 和原生等针对性用例，并执行 CI 清单、三图自检、两档模拟基线及 34 图启动。

测试使用独立 APPDATA、存档命名空间和项目副本。九个源规则文件及 627 个版本化运行素材的哈希保持不变。GitHub 工作流已配置，远程执行结果不在本轮本机验收范围；GPU、发行 EXE 和完整战场性能验收仍使用已有独立入口。

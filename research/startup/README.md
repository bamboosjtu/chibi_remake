# 原版《赤壁》全关卡开场白

> 对象：`_work/iso/CB.EXE`（SHA-256 `2db7cc102e6fde547ab05d77cfddabc2079f5bc9be9b6b59b17bf435c5798cb7`）
> 数据：`SET/BATTLE.EXP`（关卡顺序）、`MEDS/<MAP>.MED`（关卡标题）、`SET/MISSION.EXT`+`MISSION.EDX`（任务说明）
> 方法：数据解码 + 既有 Ghidra 导出交叉核对；**未运行原版**（仅使用用户提供的刘备第一关截图做对照）。
> 范围：34 关的**开场任务说明**（对话框正文）；不含触发情节文本与帮助文本。

## 结论摘要

1. 34 关开场白全部在 **`MISSION.EXT`** 里：XOR `0x46`，配 `MISSION.EDX` 的 `(u16 offset, u16 length)` 索引表，共 71 项。
   - 0–29：UI 提示（遭袭、建造完成、单挑失败等）
   - 30–34、70：空/保留项
   - 35：分节标题 `（任务说明《文字.txt》中）`
   - **36–69：34 关开场白**（正好 34 条）
   - 70：空项；EDX 表到此结束。文本文件尾部还有触发情节/帮助文本，但**不在本索引表内**，未纳入本目录。
2. 关卡顺序来自 `BATTLE.EXP`：前 17 关是**刘备线**（`chibil1..16`，含 `7a/7b`），后 17 关是**曹操线**（`chibic1..17`）。
3. 关卡标题不在 MISSION 里，而在每个 **MED 地图文件偏移 5** 的 8 字节 GBK 字段（固定 4 个汉字）。例如 `CHIBIL1.MED` = `二吕进犯`。
4. 用户提供的刘备第一关截图与数据**逐字一致**：
   - 标题：`二吕进犯`
   - 正文：`曹军距离新野不远，迅速组建一支部队，抵御曹军的进攻。`
5. `MISSION.EXP` 是另一份**旧版/变体**文本：35 条、把“投奔襄阳”拆成 3 条，且有“艰守/逃串/荆洲”等错字；游戏实际加载的是 **EXT**（`FUN_00401810("set\mission.ext", "edx")`，读取时 XOR 0x46），所以本目录以 EXT 为准。
6. 原文有一处**字库特殊字**：第 3 关“夏侯┲”中的 `┲` 是 HZK 特殊字形（惇）；输出时归一化为“夏侯惇”，并在数据里保留原文。
7. 第 11/12 关（三江水战、大战于禁）原文开场白**完全相同**（“击败曹操水军，摧毁曹军水寨。”），这是源数据如此，不是提取错误。

## 1. 数据格式与加载

### 1.1 关卡顺序 `BATTLE.EXP`

XOR `0x22` 后是文本任务表，开头 `34` 表示 34 关。按顺序提取地图名：

```text
chibil1..6, chibil7a, chibil7b, chibil8..16   （刘备 17 关）
chibic1..17                                    （曹操 17 关）
```

### 1.2 关卡标题 `MEDS/<MAP>.MED`

每个 MED 文件：

```text
offset 0..4   5 字节头（示例：65 00 00 00 08）
offset 5..12  8 字节 GBK，固定 4 个汉字（标题）
offset 13+    地图数据
```

34 个标题全部可读，且与重制版关卡列表一致（二吕进犯、计取樊城……决战柴桑）。

### 1.3 开场白 `MISSION.EXT` + `MISSION.EDX`

- `MISSION.EXT`：整表 XOR `0x46`。
- `MISSION.EDX`：每项 4 字节 = `u16 offset` + `u16 length`，指向 EXT 的字节区间（长度包含结尾的 `00 00`）。
- 加载链（既有 Ghidra 导出）：
  - `FUN_00401810("set\mission.ext", "edx")`：打开 `mission.ext`，并把扩展名换成 `edx` 打开索引；
  - `FUN_004018c0`：按索引 `fseek(edx, index*4)` → 读 `(offset,length)` → 从 EXT 读字节 → 逐字节 XOR `0x46`；
  - `FUN_0041a460(id)`：显示第 `id+1` 项；UI 消息 ID 0x15/0x16/0x17 分别对应“水军将领不能单挑/距离太远/单挑开关关闭”，验证了 +1 约定。
- 34 关开场白的表索引为 **36–69**（0 基）；正文前有全角缩进 `　　`，输出时去掉。
- EDX 表只有 71 项（0–70），最后一项 70 为空；文件尾部的事件/帮助文本在 EDX 覆盖范围之外，本目录未提取。

## 4. 数据质量说明

### 4.1 EXT 与 EXP 的差异

| 项 | MISSION.EXT（实际加载） | MISSION.EXP（旧版/变体） |
|---|---|---|
| 开场白数量 | **34** | 35 |
| 襄阳段 | 第 6 条：进入襄阳，失败则撤往江陵；第 7 条：继续撤往江陵，击退蔡瑁 | 拆成 3 条：进入襄阳 / 撤往江陵 / 击退蔡瑁 |
| 用字 | 坚守、逃窜、荆州 | 艰守、逃串、荆洲 |
| 结尾 | 每条带句号 | 部分无句号 |

游戏代码加载 `set\mission.ext` 并由 `FUN_004018c0` 以 `0x46` 解码，因此 **EXT 为准**。

### 4.2 特殊字与重复

- 第 3 关“夏侯┲”：`┲` 是 HZK 字库的特殊字形（对应“惇”）；展示字段已归一化为“夏侯惇”，`raw_briefing` 保留原字。
- 第 11/12 关开场白完全相同（源数据重复）。
- 第 6 关是条件句“如果无法进入襄阳，则部队撤往江陵”，与 7a/7b 的撤退分支对应。

4. `MISSION.EXT` 尾部（EDX 覆盖范围之外）的触发情节/帮助文本未纳入本目录（只取 36–69 的开场白）。

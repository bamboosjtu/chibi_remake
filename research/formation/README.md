# 原版《赤壁》十阵法与素材

> 目标：`CB.EXE` SHA-256 `2db7cc102e6fde547ab05d77cfddabc2079f5bc9be9b6b59b17bf435c5798cb7`。  
> 仅以原版二进制 + REA/Ghidra 静态分析为准；`docs/` 和重制实现只作差异对照。

## 0. 结论速览

- 共有 **10 种阵法**，命令 **16190–16199**，图标帧 **113–122**。
- 每种阵法固定 **15 个槽位**，每个槽位是相对锚点的 **格偏移 `(x, y)`**。
- 数据结构在 `FUN_00401970` 中运行期初始化：
  - `local_510[0]=15`；
  - 10 组，每组 `15 × (x,y)`，共 **300 个 int**；
  - 总计 **301 个 int**。
- 列阵命令由 **16133「列阵」** 打开子菜单；选择阵法后：
  - 命令 ID 映射 `formationIndex = command − 0x3F3D`，得到 **1..10**；
  - `FUN_0045F710` 读取该 index，调用 `FUN_00401950` → `FUN_00401970`；
  - 把偏移写入每个队伍成员的 `unit+0x134`、`unit+0x138`；
  - 再以执行单位**当前格**为锚点，把成员移动到 `锚点 + offset`。
- **阵法没有攻防、速度、HP、士气或动画倍率效果**；它只改变位置和后续群移动的目标点。
- 偏移是**固定表坐标**，没有按单位朝向旋转。
- 图标是名称/视觉提示，**实际槽位以 15 个坐标为准**；`formations_sheet.png` 是原版图集，布局 SVG 由坐标表生成。

## 1. 启用与执行流程

### 1.1 命令入口

- 战斗面板的 **16133「列阵」** 进入阵法子菜单；
- 子菜单命令：
  - 16190 一字长蛇阵
  - 16191 二龙出水阵
  - 16192 三才天地阵
  - 16193 四象奇门阵
  - 16194 五行梅花阵
  - 16195 六合连环阵
  - 16196 七星北斗阵
  - 16197 八门金锁阵
  - 16198 九宫八卦阵
  - 16199 十面埋伏阵

`FUN_00428A50` 中的分派：

```c
if (0x3F3D < command && command < 0x3F48) {
    DAT_004b7efc = 10;                 // action mode 10
    DAT_004b7f00 = command - 0x3F3D;   // 1..10
}
```

### 1.2 一次列阵动作

等级与子菜单订正：`FUN_004288C0` 的第一页掩码按等级 0–9 为 `[7,7,7,63,63,255,511,511,511,511]`，第二页为 `[0,0,0,0,0,0,259,259,259,259]`。第一页前八格是一至八阵，第九格是向下翻页；第二页前两格是九、十阵，第九格向上翻页。因此 0–2 级三阵、3–4 级六阵、5 级八阵、6–9 级十阵。

`FUN_0040D9C0` 的面板 `0x11242/0x1124C` 分别绑定数组 `0x49AB38/0x49C748`；`0x418A8E–0x418AFC` 写入上述按钮表，`FUN_00455ED0` 提供三列九格的 40 像素步距。此项由本地 Capstone 对同哈希文件只读核对，结合用户提供的三阵截图确认；不作为新 REA Evidence。子菜单无返回条，点击战场退出。

`FUN_0045F710`（action mode 10）：

```c
FUN_00401950(unit, unit->formationIndex);   // index-1
FUN_00424980(1, unit, members, 15);          // 队伍成员，最多15

for (member in members) {
    targetX = member->offsetX + unit->tileX;
    targetY = member->offsetY + unit->tileY;
    queue_move(member, targetX, targetY);
}
```

- `FUN_00401950(unit, n)` 只是调用 `FUN_00401970(unit, n-1)`；
- `FUN_00401970` 按 index 选择 30 个 int（15 对）；
- 结果写入每个成员的 `+0x134` / `+0x138`；
- 每个成员收到一个 **mode 2 移动任务**，目标 = **执行单位当前格 + 该成员偏移**；
- 动作完成后 `unit+0x70=1`。

> 代码路径中 `FUN_0045F710` 使用执行单位自身的 `+0x1A/+0x1C` 作为锚点，没有读取额外的地面点击坐标。  
> 因而“列阵”是以当前队伍位置为中心重新排位，不是先选一个地面目标点再展开。

### 1.3 之后群移动为什么保持阵形

`FUN_0042A8A0` 的 mode 2 群移动路径会读取每个成员已保存的偏移：

```c
targetX = unit->offsetX + mouseTileX;
targetY = unit->offsetY + mouseTileY;
```

所以：

- 列阵动作负责**写入偏移**；
- 之后的群移动负责**复用偏移**：鼠标目标格 + 各成员偏移；
- 阵形在移动时保持表坐标，不随点击方向旋转。

## 2. 数据结构

`FUN_00401970` 的局部数组：

```text
local_510[0]      = 0xF (15)        // 成员容量
local_510[1..300] = 10 × 15 × (x,y) // 每种阵法的槽位
```

访问：

```text
formationIndex0 = formationIndex - 1   // 0..9
pair = local_510 + formationIndex0 * 0x1E + 1
```

- 坐标单位：**格**（不是屏幕像素）；
- `x` 向右；
- `y` 使用原表值；屏幕绘制时负值向上；
- 第一个槽位是 `FUN_00424980` 返回列表的第一个成员，通常是武将/队长；
- 队伍少于15人时只使用前 N 个槽位；
- 表仍固定提供15个槽位，没有按人数重新计算几何。

### 2.1 槽位顺序

`FUN_00401970` 末尾：

```c
piVar6 = local_510 + formationIndex * 0x1E + 1;
for (i = 0; i < memberCount; i++) {
    offsetX = *piVar6++;
    offsetY = *piVar6++;
    member->+0x134 = offsetX;
    member->+0x138 = offsetY;
}
```

所以槽位编号 1..15 是**表顺序**，不是按距离或兵种重新排序。

## 6. 机制与限制

- **无属性加成**：没有修改攻击、防御、HP、士气、移动/攻击速率；只写位置偏移与移动目标。
- **无朝向旋转**：表和群移动都直接相加，没有旋转矩阵；阵形固定在世界坐标轴上。
- **锚点是执行单位当前格**：`FUN_0045F710` 使用 `unit+0x1A/+0x1C`，不是鼠标点击地面。
- **15 槽位固定**：队伍不足15人时取前缀；表格不会按人数收缩或重新居中。
- **首槽位**：`FUN_00424980` 列表第一个成员，通常是武将/队长；点成员时可能先解析到队长。
- **群移动保持**：`FUN_0042A8A0` 的 mode 2 在鼠标目标上叠加 `+0x134/+0x138`；因此阵形会随群移动复用。
- **不是碰撞/攻击范围**：表坐标仅决定站位，图标上的星/线/门不是 AOE。
- **翻页**：16200/16201 是子菜单翻页按钮；不改变阵法几何。
- 本文没有运行原版做逐帧验证；坐标来自运行期初始化代码的静态还原。

## 6.1 与 docs/08 的差异

`docs/08-abilities.md` §3 的总体方向正确（纯队形、无属性加成、最多15、点击格+偏移），需要补充/修正三点：

1. **第一个偏移不一定是 (0,0)**：槽位1是队伍列表首个成员，但表值可能是 `(0,-4)`、`(0,-6)` 等；不要把队长固定留在锚点。
2. **锚点是执行单位当前格**：`FUN_0045F710` 读取 `unit+0x1A/+0x1C`；列阵本身没有额外的地面点击坐标。
3. **固定朝向**：表偏移直接相加，没有旋转矩阵；群移动时也不按点击方向旋转。
4. 群移动的边界夹取是 `x∈[3,mapW−4]`、`y∈[3,mapH−3]`（`FUN_0042A8A0` mode2）。

# 原版《赤壁》建筑与建造机制

> 目标：把 `CB.EXE` 里的 **27 类建筑**、建造菜单、建造前置、工地/施工、生产/研究/出售、资源点（含民居）以及原始素材一次讲清。  
> 方法：REA/Ghidra 静态分析 + `DATA.EXP` / `UNIT.EXP` / `INTERFAC.EXP` / `PROMPT` 解码 + `UNIT.LWC` / `BMP.LWC` 原图提取。  
> 口径：**原版代码/数据是唯一依据**；`docs/` 与重制实现只在差异/修复段落出现，不能反过来证明原版行为。  
> 跨包修复：工人费用、生产档位/500 档见 [`research/units/REMAKE_FIXES.md`](../units/REMAKE_FIXES.md)；建筑费用、前置、可建范围见本文 §12。

## 结论摘要

1. 建筑类型 ID 固定为 **0–26**，共 27 条记录。大多数成对出现（0/1、2/3、…），是**两个阵营/两套美术**，规则相同；单 ID 有 20 船坞、21 特殊、22 铁矿、23 钱庄、26 大旗。
2. 原版建筑费用字段的真实运行时映射是：**铁 = v[7]，粮 = v[8]，木 = v[9]，金 = v[10]**（`FUN_0041FF30` + `FUN_00421B50`）。因此普通建筑都是 **金 30**，而不是 docs/重制表里的“金 1000、粮 0”。这是本轮最重要的数据订正。
3. 建造菜单不是 27 项全列：原版用 `16150+typeId` 的命令，分 **A/B 两套阵营美术**；`0x111DE` 工人建造菜单第一页是 9 项（帅帐、粮仓、木材场、武器库、钱庄、步兵所、弓兵所、骑兵所、车兵所），翻页/第二菜单再放船坞、箭楼、大旗、城门等。
4. **原版建造前置**不是写在费用检查里，而是写在建造菜单掩码 `FUN_00428810`：它读取 **帅帐、粮仓、木材场、武器库** 是否存在，清掉对应菜单位。按 `0x111DE` 的按钮顺序推断，第一页的依赖是：
   - 钱庄 ← 帅帐；
   - 步兵所 ← 粮仓；
   - 弓兵所 ← 木材场；
   - 骑兵所 ← 粮仓 + 木材场；
   - 帅帐/粮仓/木材场/武器库/车兵所无前置。
   这套结论与 docs 的“骑兵所 ← 武器库”不同；`武器库` 标志实际用于**第二个建造菜单**（建筑侧/高级页），该页的逐位映射仍需实机截图最终确认。
5. 工地从 **HP=0** 开始；每名工人在 **每 4 tick** 给工地 **+2 HP**，多人叠加。`FUN_0045E130` 在 **1/3、2/3、满** 三个阈值换帧/完工，并按建筑类型的击杀经验给施工队所辖武将加经验。
6. 产出分五类：**训练单位**（帅帐/步兵所/弓兵所/骑兵所/车兵所/船坞）、**研究**（木材场/武器库/车兵所/船坞/帅帐）、**出售**（钱庄 6 项）、**粮容**（帅帐/粮仓各 +10000）、**资源点/防御/通行**（铁矿、民居、箭楼、城门、大旗）。
7. **民居（民房）24/25 不可建造**：它是 500 金的资源点，2×2、800 HP、视野 0；三趟 200/200/100 取完消失。建造图标 16186/16187 是“民居信息”图标，不是可执行建造命令。
8. 原始建筑有多帧：多数 2 帧（完好/损毁），帅帐 10/8 帧，船坞 3 帧，特殊 6 帧，铁矿 3 帧，民居 3/2 帧。帧 0 = 完好/满存量，末帧 = 损毁/枯竭；工地按 HP 阈值反向取“残破→完好”。

## 4. 建造前置：原版代码 vs 重制设计

### 4.1 原版：菜单掩码，不是费用检查

`FUN_0041FF30` 只检查四项资源够不够；它**不看**已有建筑。真正的建造前置在 `FUN_00428810`：读取每方“第一个该类建筑”的存在标志，清掉建造菜单的位。

`FUN_00460610` 会为每方记录以下标志（`100` = 已存在）：

- `DAT_005af2a4`：帅帐 0/1
- `DAT_005af2c4`：粮仓 10/11
- `DAT_005af2e4`：木材场 4/5
- `DAT_005af2ec`：武器库 2/3
- 以及骑兵所/车兵所/步兵所/弓兵所/箭楼/船坞/钱庄等的对应槽位。

`0x111DE` 的 9 个按钮指针顺序与掩码位：

|---:|---|---:|---:|---|
| bit0 | `0x4A0230` | 16150 | 0 帅帐 | — |
| bit1 | `0x496E18` | 16160 | 10 粮仓 | — |
| bit2 | `0x49BFA8` | 16154 | 4 木材场 | — |
| bit3 | `0x498EF8` | 16152 | 2 武器库 | — |
| bit4 | `0x497B38` | 16173 | 23 钱庄 | 帅帐不存在 → 清 |
| bit5 | `0x4958A8` | 16162 | 12 步兵所 | 粮仓不存在 → 清 |

## 5. 建造流程、工地与施工

### 5.1 入口

1. 选择**带工人的武将队伍**（武将本人或队内工人均可）；独立工人不能发起建造（需先组建）。
2. 命令面板「建造」→ 选择条目。
3. 地图选点；原版先调用 `FUN_0041FF30` 检查资源，再 `FUN_00457860` 载入建筑预览图，进入建造模式。
4. 确认后 `FUN_0045C320` 创建工地/派工。

### 5.2 费用与工地

- 费用：**金、木、粮、铁**四项；建筑费用见 §2.1。
- 工地初始 HP = 0，仍占整块占地；已建成建筑才提供视野。
- 施工入口要求至少一名随队工人能到达工地边缘；工人进入工地内部，退出占格/索敌/选框。

### 5.3 施工节拍

`FUN_0045C320` 的施工分支：

```
if ((uVar13 & 3) == 0) { site.hp += 2; }
```

- 每名工人每 **4 tick** 给工地 **+2 HP**；多名工人叠加。
- 工地 HP 达到类型 HP 后完工；`FUN_0045E130` 负责阶段换帧/完工。

### 5.4 工地阶段与换帧

`FUN_0045E130` 用三个阈值：

- HP ≥ 0：阶段 1；
- HP ≥ max/3：阶段 2；
- HP ≥ 2×max/3：阶段 3；
- HP ≥ max：完工。

帅帐 0/1 的精确帧偏移（代码）：

| 工地 HP | 帧 |
|---|---|
| 0 | `firstFrame + 9` |
| ≥1/3 | `firstFrame + 8` |
| ≥2/3 | `firstFrame + 1` |
| 满 | `firstFrame + 0` |

### 5.5 完工、经验、取消、修理

- 完工时按建筑类型的 `killXp` 给施工队所辖武将加经验并检查升级（`FUN_0045E130` / `FUN_0045C320`）。

- 每方实体上限 **200**（docs/重制；原版分配器有上限检查，未在本轮逐行核对）。
- 建筑工作锁：生产、研究、出售、施工互斥；不同建筑可并行（docs/重制）。

## 3. 参战方配置

`scenario.sides` 每项字段：

| 字段 | 含义 |
|---|---|
| `owner` | 归属编号 |
| `init[0]` | AI 行为档位（0/1/2） |
| `init[1]` | 科技门槛（1–4） |
| `init[2]` | 信息面板变体标志（0/1）；保留字段，当前界面不区分 |
| `resources` | 初始资源，顺序为**金、粮、木、铁** |
| `roster` | 武将全局索引 +1 的列表 |
| `ranks` | 与 `roster` 对应的档次 |

- 玩家归属固定取 `sides[0].owner`；单机不使用“第二方”模式。
- 初始资源写入该方资源池；HUD 资源栏按金、粮、木、铁显示。
- `init` 不是胜负条件；胜负由任务号与关卡目标决定。

## 4. 开局生成

### 4.1 地图对象

- `objects` 按顺序生成；`objects` 的段号即归属（0–4）。
- 每个对象带类型、格坐标、像素位置与图集；资源点还带存量（本版本统一取值，见 03 章）。
- 单位尾部字段：
  - 可编组部队（27、28、30、32、34、36–46、48、49）：**统辖武将编号**，0 表示不编组；
  - 铁矿/民居：资源存量；
  - 其余建筑：无尾部。

### 4.2 武将登场

1. 对每个参战方，按名单顺序取武将；
2. 该武将在本图有部队（部队尾部 = 武将索引 + 1）时登场；
3. 在该武将**首支部队的位置**生成武将本体；
4. 等级 = 档次 − 1（档次 0 用武将库默认等级；索引 1–33 且等级 0 时置 5）；
5. 生命取类型基础值，士气 70，谋略 10；
6. 同编号的其余部队编入该武将名下。

名单中无部队的武将不登场；未编组部队（编号 0）保持无将状态，可通过「组建」使用。

### 4.3 开局编制

- 每队最多 15 名成员，武将另计；本版本 34 关共有 18 支满编（15 人）初始队伍。
- 超出 15 名的成员保留为未编组单位，不销毁。
- 开局选中第一支我方武将队伍，并占用控制组 1。

## 5. 任务与胜负

### 5.1 默认规则

| 结果 | 条件 |
|---|---|
| 胜利 | 所有敌对参战方的机动单位与建筑均清空 |
| 失败 | （金为 0 或我军机动单位为 0）且我军建筑为 0 |

敌对参战方取 `sides[1..]`；没有战役数据时按“除我与非中立归属外都是敌人”。

### 5.2 脚本目标

8 个任务带脚本阶段，其余 26 关走默认规则：

| 任务 | 关卡 | 阶段与条件 | 效果 | 胜利出口 |

规则：

- 每段独立锁存，效果只执行一次；`requires` 指定前置段。
- 区域矩形为闭区间格坐标 `[A0..A1]×[B0..B1]`，对应单位的 `(A, B)`。
- “士气 ±N”指该任务指定方全体武将士气变化，不是资源。
- “事件 N”按 `data/db/events.json` 播放视频或显示文本；播放期间模拟暂停。
- 旧 `enemy_order.experienceParameter` 写入独立的事件进度字节，缺省 100、按字节回绕；它不是武将升级经验。
- 武将事件经验使用独立的 `officer_experience` 效果，必须提供明确的经验量或已解析的地图参数。
- 任务 14/30 的前两段命中后本 tick 让行，下次再检查后续段；第三段不强制前两段完成。
- 任务 29 的第 3 方按参战方序号取（`sideIndex = 2`），清空判定包含单位与建筑。
- 任务 5 的终点条件独立求值，不受第一段锁存阻塞。

### 5.3 任务数据

`data/db/scenario_rules.json` 的 `missions` 结构：

```json
{
  "5": {
    "stages": [
      { "id": "a", "condition": {...}, "effects": [...] },
      { "id": "win", "condition": {...}, "win": true }
    ]
  }
}
```

条件类型：

| 类型 | 字段 |
|---|---|
| `officer_in_rect` | `officer`、`rect` |
| `unit_in_rect` | `rect`、可选 `side` |
| `officers_near` | `officer`、`otherOfficer`、`otherSide`、`radius` |
| `unit_type_present` | `unit` |
| `enemy_mobile_present` | — |
| `all` | `conditions` |
| `side_cleared` | `sideIndex` |

效果类型：

| 类型 | 字段 |
|---|---|
| `status_delta` | `side`、`amount` |
| `event` | `id` |
| `clear_tiles` | `layer`、`cells` |
| `enemy_order` | `target`、`experienceParameter` |
| `officer_experience` | 一基 `officer`、`side`（默认 player）、`amount` 或 `experienceParameter` |

## 6. 媒体与事件

| 项 | 规则 |
|---|---|
| 开场 | 进入关卡时播放 `media/videos/<开场片名大写>.AVI`，任意键跳过；结束或跳过后显示任务开场白 |
| 任务开场白 | 34 关逐关采用 `research/startup` 的 MISSION.EXT 标题与正文；暂停模拟，点击「完成」或 Enter/空格/Esc 继续；缺少视频时直接显示 |
| 重看任务 | 系统菜单「战役任务」打开同一正文；关闭后仍停留在暂停菜单；读取存档不重播开场 |
| 事件 | `data/db/events.json` 指定视频或文本；同一事件只播放一次，读档不重播 |
| 结局 | 不播放结局视频；胜利进入下一关或战役完成面板 |
| 播放行为 | 视频按原生分辨率的整数倍居中显示，最近邻放大；播放期间暂停模拟 |

## 7. 胜负结算

- 胜利/失败后显示对应文字，模拟冻结。
- 胜利且存在下一关：5 秒倒计时自动进入下一关，可点「留在战场」取消；失败或终章显示战役结束/完成。
- 不写战役完成状态、不播放结局；玩家可通过面板或暂停菜单返回主菜单、读取其他关卡存档。

## 9. 验收要点

- 34 关全部可进入，玩家归属、初始资源、名单与档次与关卡数据一致。
- 开局武将在首支部队位置生成；无部队的武将不出场。
- 脚本阶段逐段锁存，效果只执行一次；胜利出口与默认歼灭规则分离。
- 任务 29 在第 3 方清空时胜利，即使第 2 方仍存活。
- 事件视频播放期间暂停模拟，读档不重播。

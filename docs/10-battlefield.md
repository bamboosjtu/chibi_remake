# 10 战场

> 本章定义地图数据、等距网格、导航与占格、城门和视野。地图的战役含义见[战役](11-campaign.md)；地形美术见[美术规格](17-art.md)。

## 1. 地图数据

每张地图一个 JSON：`data/<地图 ID>.json`。地图 ID 为 `chibic1`–`chibic17`、`chibil1`–`chibil16`（含 `chibil7a`、`chibil7b`），共 34 张。

| 字段 | 含义 |
|---|---|
| `name` | 关卡名，如「侦察新野」 |
| `map` | 地图资源名，如 `CHIBIC1` |
| `scenario` | 战役参数：任务号、开场片名、参战方 |
| `terrain` | 地形分块清单路径 |
| `terrainW` / `terrainH` | 世界像素尺寸 |
| `tileW` | 格宽（固定 44 像素） |
| `rows` / `cols` | 格坐标范围（行 / 列） |
| `walkable` / `terrainWalkable` | 地格通行表（0 不可走，1 可走） |
| `waterWalkable` | 水面通行表；纯陆战图全 0，水面层关闭 |
| `decor` | 地形饰物：`[行, 列, 相位]` |
| `objects` | 地图对象：归属、类型、格坐标、像素位置、图集 |
| `units` | 本图使用的单位/建筑类型定义 |
| `navigation` | 导航元数据（拓扑、占用方式） |

地图尺寸共有四种：

| 行 × 列 | 世界像素 | 使用关卡 |
|---|---|---|
| 90 × 270 | 4048 × 3130 | 两条线的前两关 |
| 105 × 305 | 4708 × 3515 | 第 3、5 关等 |
| 105 × 315 | 4708 × 3625 | 第 4 关 |
| 120 × 360 | 5368 × 4120 | 中后期关卡 |

## 2. 等距网格

### 2.1 坐标换算

```
格 → 像素（脚底锚点）：
  x = 44 × A + 22 × (B & 1) + 22
  y = 11 × B + 22

像素 → 格：
  B = round((y − 22) / 11)
  A = round((x − 22 − 22 × (B & 1)) / 44)
```

- `A` 为行，`B` 为列；交错行在横向上有 22 像素偏移。
- 所有单位、建筑、资源点、饰物都用同一套锚点公式；地图对象的 `px/py` 是精灵左上角，锚点由 `px + w/2`、`py + h` 得到。

### 2.2 邻接

每个格有 4 个邻格（菱形四边）：

```
邻格 = (A + dx, B ± 1)，其中 dx = 0 或 (B 为奇数 ? +1 : −1)
```

实现按 `B` 的奇偶选择横向偏移，并对所有格建立双向连接；路径代价按锚点世界距离计算。

## 3. 导航

### 3.1 双层

| 层 | 使用单位 | 通行表 |
|---|---|---|
| 陆地层（0） | 陆军、工人、武将、建筑 | `terrainWalkable` |
| 水面层（1） | 水军 46/48/49、运输船 47、旗舰 52 | `waterWalkable` |

- 水面层无数据或全图无水面时整层关闭，水军不存在于该图。
- 陆军与海军不共享路径；只有同层且起点一致时才复用路径。

### 3.2 阻挡

一个格不可通行，当且仅当满足任一条件：

- 通行表中该格为 0；
- 被建筑占地占用（占用计数 > 0）；
- 被封格（运行时清除地形/桥）；
- 属于关闭的城门通道。

地形阻挡与建筑占用分别计数；建筑摧毁时释放整片占地。

### 3.3 寻路

| 规则 | 说明 |
|---|---|
| 算法 | 交错网格 A*，按世界距离计代价 |
| 不可达 | 返回空数组；**绝不**退化为直线穿墙 |
| 起点吸附 | 起点不可走时，在周围 5 圈内找“可走且从当前位置看得见”的格作为出发格 |
| 终点吸附 | 终点取最近可放格；最后一段必须通过通行采样 |
| 动态阻挡 | 路径失效时按新世界重算；绕不开才放弃目的地 |
| 避让 | 对起点/终点 12 格内的其他单位整块占格做临时禁格，查询后恢复 |
| 路径拉直 | 在同一查询图中采样检查直线可达，保留临时避让、整块身体和城门路点，合并交错格折线 |

### 3.4 移动

| 项 | 规则 |
|---|---|
| 基础速度 | 110 像素 / 秒 |
| 加速 | 地面×2；船类不额外叠加 |
| 减速 | ×0.5 |
| 步进 | 每 tick 完整消费 `速度 × 1/30` 的距离；短路点与重复路点不丢掉剩余步长 |
| 到达 | 走完最后一段、提交准确终点；整队预先分配各自占格，避免争抢同一终点 |
| 画面 | 在相邻模拟位置间逐显示帧插值，不改模拟、索敌和存档坐标；位移型操作直接落位 |
| 行走动画 | 每两次逻辑更新推进一帧；默认 30ms 档为 60ms/帧；使用各类型/方向完整 动画 序列，独立于动作速率 |
| 连续受阻 | 同一路径连续 3 次无法前进则放弃 |
| 新占地 | 当前段被新建筑/封格截断时保存目的地并重算；不可达则停下 |

### 3.5 防叠

- 士兵、工人、武将、船只不能站在同一格。
- 行军途中允许穿过拥挤格；到达或待机后，若与其他单位重叠，则以正常步行速度让到最近的**可连通**空格。
- 让位只接受几何与路径都连通的格，不能跨越墙、水岸或封闭地形。
- 找不到合法空位时保持原位，不瞬移。

### 3.6 地形显示与停顿

运行时按镜头周边请求分块，最多两个后台任务读取并解码 CPU 图像，主线程每显示帧最多上传一个已完成纹理。离开视野的分块按最近使用顺序保留与回收；实际工作集限制为 384 MiB 硬上限的 94%，为纹理上传和缓存替换留出至少 6% 余量。LOD 选择与回收使用同一工作集上限。关卡退出前等待后台任务结束，任务不访问场景节点。显式检视接口可同步完成加载，供资源与内存验证使用。

资源自动转采按连通资源片去重：同一片粮田或森林只求一次边缘路线，再按原有实际路径长度规则比较，避免对每一格重复搜索整片资源。

视野未揭开的敌军与镜头外单位继续参与模拟，但不切换高清动画纹理；进入镜头后按当前动画时间刷新。未变化的动画帧与建筑选中轮廓复用已有结果。

## 4. 占格

### 4.1 档位

| 档 | 格数 | 单位 |
|---|---:|---|
| 0 | 1 | 工人、平民、武将本体、100 人步兵/弓兵、快船、箭楼、大旗、特殊 |
| 1 | 4 | 200 人骑兵、500/1000 人兵种、车兵、运输船、战船、粮仓、步兵所、弓兵所、城门、民居 |
| 2 | 9 | 大本营、武器库、木材场、骑兵所、车兵所、船坞、铁矿、钱庄 |
| 3 | 16 | 连船 49 |

- 形状为固定偏移表，按锚点 `B` 的奇偶分两套；档 N 取前 N² 项。
- 单位与建筑共用同一套形状规则；图片宽高不参与占格。

### 4.2 整块寻路

- 多格单位按整块身体寻路：每层、每档按需建立形状图，只启用身体放得下的锚点。
- 占格、封格、城门变化只标记受影响锚点，查询前增量刷新。
- 移动提交前再做一次整块扫掠校验，防止拐角蹭墙。
- 出生、装载、下船、死亡时增量维护占格索引；每 tick 的防叠与落点查询不扫描全体单位。

## 5. 城门

| 项 | 规则 |
|---|---|
| 类型 | 16 / 17，占 2×2 |
| 通道 | 门洞格由关卡地形给出；城门控制其开闭 |
| 开启 | 归属方机动单位在门洞内，或在感知范围内且路径经过该门 |
| 感知范围 | 横向 ±2.5 格、纵向 ±8×11 像素的椭圆 |
| 敌军 | 不能触发开启 |
| 友军优先 | 友军与敌军同时接近时优先开启 |
| 寻路 | 友军规划时可临时穿越己方关闭城门；行走提交校验真实状态 |
| 状态 | 开闭变化递增导航版本，路径失效并重算 |
| 摧毁 | 释放通道并移除城门 |
| 重建 | 地图加载与读档后按实际位置重算 |

## 6. 视野与迷雾

### 6.1 遮罩

- 遮罩按 22 × 11 像素的子格划分（一个地形格横向、纵向各 2 个子格）。
- 每格维护三个量：当前可见、已探索、揭示来源计数。
- 揭示半径：

```
有效视野 = 远视状态 ? 10 : 类型视野 × 2
半径（子格）= (有效视野 + 0.5) × 2
判定：|dx| + |dy| ≤ 半径
```

- 重叠揭示按来源计数；只有最后一个来源离开时，该格才从可见恢复为暗区。
- 已探索格永久保留记忆，不再变黑。当前可见格的遮罩 alpha 为 0，已探索但不可见为 165/255，未探索为 1。读档提交新世界后，大地图遮罩重新绑定当前视野对象；即使暂停也刷新，不依赖旧对象的修订号。

### 6.2 来源

| 来源 | 是否提供视野 |
|---|---|
| 玩家机动单位 | 是（存活、未上船、未隐藏） |
| 玩家已建成建筑 | 是；工地不提供 |
| 载员 | 否（跟随船的位置） |
| 敌方单位 | 否（不会为玩家揭雾） |
| 死亡/淡出 | 否 |

- 建筑视野：箭楼 8，城门/钱庄/大旗 6，其余 5，铁矿与民居 0。
- 单位视野见[单位与武将](07-units-officers.md#1-单位类型)。

### 6.3 远视

远视状态把有效视野固定为 10；到期恢复基础视野。已探索记忆在到期后保留。

## 10. 验收要点

- 不可达目标返回失败并提示，不生成穿墙路径。
- 多格单位的整块身体不穿越窄门、岸线与封闭地形。
- 防叠只移动到可连通空格，不跨越阻挡。
- 城门开闭与通行、画面一致；敌军不能开门。
- 迷雾重叠来源按计数恢复；远视到期恢复基础视野且保留探索记忆。

### 小地图探索地形

小地图使用同一套高清地形的离线缩略图，运行时不遍历加载整图地形块。当前可见区域显示正常亮度，已探索但当前不可见区域显示暗色地形，未探索区域保持黑色；直接复用战场迷雾纹理，读取原有 explored 存档。敌军标记仅在当前视野内显示，不透视未知区域。

刘备第一关原始敌军位于城外东北区域，包含 19 个士兵实体和 2 个将领本体。玩家兵力不少于 6 实体且敌方等级未达关卡门槛时，金钱不足 15000 会使敌军等待；该对照规则战略出兵条件保留；局部遭遇接战独立运行，接近驻军时双方空闲部队会作战。

### 基于 research/movements 的行走与转向

逻辑档位已有 20/30/50/100ms 周期，本次保留战场节拍与移动距离，修正固定 10fps 步态和瞬切朝向。`simulation/systems/locomotion.gd` 维护独立 `walk_tick`，仅在实际移动时推进，每两次更新选下一帧；跨路点、转向和重复命令不清零。各方向按步态行 `turn` 的完整序列循环并保留重复帧；`walk` 标签对应的动作行只用于站定攻击/修理，不因其名称而用于位移。v8 继续只用于攻击/修理周期。

显示 `move_facing` 与路径 `dir` 分开，每两次更新向目标方向转一个相邻扇区并使用 turn 姿势，移动起步保留短过渡；不等待转身结束才位移。显示层采用独立转向模型。位置和行走相位一起插值；镜头外继续计数而不加载高清帧。移动中携带资源仍用搬运序列，停下攻击/修理仍由 ActionClock 控制。

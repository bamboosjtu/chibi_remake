# 16 存档格式与事务

> 本章规定当前存档格式、文件提交、候选世界恢复及拒绝策略。流程见[游戏流程](../10-world/01-game-flow.md)，字段见[数据规格](02-data-spec.md)。

## 1. 单一格式

仅支持 SaveFormat.VERSION 定义的 v9。v1–v8、缺少版本、缺少 checksum、旧规则别名与旧目录迁移均不支持；不尝试转换，也不覆盖原文件。版本不支持的记录在列表中标注“格式不支持或数据无效”，当前战场保留。

Game、SaveEnvelope 和恢复器共用版本定义。RulesIdentity 只比较当前 ABI 与有效目录投影的确切规则指纹；contentRevision 比较准备完成的只读地图定义。保存使用已安装世界的地图 ID 和内容身份。配置目录有效值等价迁移保留 v9 指纹。构建源码与原生二进制的哈希用于完整性校验，不直接成为规则指纹。

## 2. 文件结构

顶层必需字段为 v、kind、map、nextUid、gameEnd、units、resources、trainings、simulation、checksum。kind 必须为 save；nextUid 为非负 32 位整数；gameEnd 为 0、1、2。resources 必须且只能包含 gold、wood、food、stone 四个有限非负值。

单位记录由 UnitSchema 的 record 组完整生成，包括 UID、类型、归属、位置、HP、存活、状态、地图对象标记和武将索引。UID 唯一，building 与兵种分类一致。simulation 使用 Schema 的持久字段及关系编码；写入前检查必需标量和关系字段，拒绝 null、未知字段和派生格缓存。既有兼容 v9 的可省略字段沿用读取缺省。库存 stock/stock_max 是显式可选能力，普通建筑不能因缺省填零获得资源点身份。

所有整数先检查有符号 32 位范围再转换，更窄的字段范围继续生效。rngState 单独使用有符号 64 位十进制字符串；tick 非负，speedIndex 为 0–3，accumulator 有限且非负。单位状态只接受已登记目录。

生产记录使用 buildingUid、owner、unit、t、ticks、cost；ticks 必须为 true，t 为非负整数逻辑 tick。费用共用 ResourceCost，只接受四种资源的有限非负数，允许省略零成本键。研究仅使用带建筑 UID 的 researchJobs 队列，不再支持无引用的单项研究槽。

## 3. 空间与引用

位置、路径、重寻路点、施工入口和 spent 资源点必须位于画布内，并能表示为有限 Vector2。路径最多 rows×cols+2 个点；空路径游标必须为 0，非空路径游标必须小于长度。运行中已结束路径的瞬态游标在写出时由 Schema 规范化，读取器不修补非法记录。

A/B 为派生格缓存，不落盘，按恢复位置重算。build/repair/board 强工作引用必须存在或为 -1。攻击、加入和采集目标允许对象刚被清理的执行窗口；悬空对象引用变为 null，加入 UID 变为 -1，供执行器清理命令。动作时钟目标和上次攻击者是历史标记，允许对象已离场，但仍检查数值范围。spent 编码保存资源种类和有界原位置。

载员必须使用 boarded 状态和有效同方船 UID；人数、HP、容量与汇总一致，死亡载员不保留船引用。状态计时只接受整数 tick，旧秒制计时、hidden 标记、旧载员摘要和单位跟随燃烧均不迁移。火场使用独立 fireFields 表。

## 4. 有界解析

JsonStore 在 JSON 解析前限制文件为 32 MiB、容器深度为 64，字符串内的括号与转义不参与结构计数。提交同样执行限制。taskLatches/taskEvents 各最多 4096 项，两棵树合计最多 32768 值节点、深度 8；键最长 256 字符，字符串值最长 65536 字符。事件 id 为非负整数，tick 缺省 0；有界扩展数据保留。

文件准入验证结构、checksum 和与安装地图无关的约束。候选进一步验证地图身份、科技、队列、载员、施工和世界引用；文件有效不代表路径在当前地形可走，也不等同于地图/规则兼容。

## 5. 写入与备份

自动记录使用槽 0，手工槽为 1–20。等待应用的命令须在自然 tick 完成后再取快照。若当前暂停令牌阻止推进，保存返回可重试错误并保留槽位。先写同目录的唯一临时文件、flush、读回验证，再轮换和替换。失败保留旧主档或备份。只有结构和 checksum 都有效的主档才能替换最后一份好备份；损坏主档隔离，失败详情包含阶段、路径和系统错误。

新快照在写入前完成 JSON 和领域校验，临时文件与提交后的主档均逐字节比对这份已校验内容。校验和继续使用 v9 的递归键排序和数值归一规则。

read_slot 返回 data 与 source（primary、backup、none）；列表标题和实际读档反馈明确显示“使用备份”。槽位缓存签名包含长度、修改时间和内容 SHA-256，覆盖同大小同修改时间的外部替换；超限文件不读全文哈希。读取不修改文件。

## 6. 世界交换

校验完整记录后，在独立 BattleWorld 内恢复单位、资源、队列、时钟、探索和服务状态，建立同一组合根。同图与跨图均在同一战场场景内换世界。跨图由 CampaignSession 在视图验证后提交地图身份。表现安装失败时恢复原世界、节点与地形，释放事务拥有的暂停令牌。

生产费用、AI 资源池、研究费用和可变数组由新世界拥有，修改输入快照不会改变恢复后的世界。成功加载清除旧输入与待执行命令；UID 命令附带世界身份，旧世界的相同 UID 不能影响替换世界。派生缓存、原生查询、纹理和读模型按新身份重建，不进入玩家快照。

## 7. 验证

test_current_format 验证当前格式读写、旧版本和缺失身份拒绝，并使用历史 v9 夹具检查同图、跨图、备份及续跑；test_save_validity/test_save_boundaries 验证正确 checksum 下的坏字段、有界解析、备份保护与输入隔离。读写续跑、原生/脚本对照和世界回滚分别由完整场景测试覆盖。测试套件是工具清单的权威来源，不由本章固定计数。

## 保存查询边界

保存准备和序列化不修改活体模拟记录。运输船人数、兵力与 loaded，以及死亡载员的存档引用，按当前单位关系投影到输出；tick 和运输命令仍负责运行时派生汇总。读档恢复校验同一份规范载员关系，不能依靠保存动作修复世界。

便携存储显式启用。`--portable-root` 接受本地完整绝对路径，或相对可执行文件目录的路径；分隔符与 `.` 规范化，拒绝 `..`、盘符相对路径、磁盘根目录、网络/设备路径、资源 URI 和非法文件字符。`portable.txt` 使用同一解析规则，空内容代表 `userdata`。非法显式配置拒绝启动，不静默改写系统存档目录。每个根目录下再使用经过文件名校验的用户子目录。

# 14 技术架构

> 本章定义运行时分层、模块职责、数据流、确定性与性能预算。数据字段见[数据规格](15-data-spec.md)，存档见[存档与兼容](16-save-compat.md)。

## 1. 运行形态

| 项 | 值 |
|---|---|
| 引擎 | Godot 4.7.2，GL Compatibility 渲染器 |
| 语言 | GDScript |
| 主场景 | `menu.tscn` |
| 自动加载 | `Game`（`app/game.gd`） |
| 窗口 | 1920×1080，`canvas_items` 拉伸、`expand` 宽高比 |
| 纹理过滤 | 最近邻（保持像素风） |
| 平台 | Windows x86_64 |
| 逻辑帧率 | 30 tick/秒，固定步长 |

## 2. 分层与依赖

| 层 | 目录 | 职责 |
|---|---|---|
| 场景装配 | `main.gd`、`menu.gd`、`presentation/battle/battle_view.gd` | 生命周期、组件连接与外部兼容入口 |
| 应用服务 | `app/` | 世界加载、存档事务、场景节点与用户存储 |
| 模拟 | `simulation/` | 独立状态、命令、规则、固定 tick、导航与 AI |
| 表现 | `presentation/` | 节点、HUD、菜单、相机、动画、音视频 |
| 数据 | `data/`、`media/`、`art/` | 稳定数据格式与素材 |
| 工具 | `tools/` | 导出、构建、回归、验证与发布 |

模拟不引用应用或表现模块，不持有场景节点。场景通过 `battle_effects` 同步接收外观与声音请求；有视图与无视图使用相同模拟数据。系统通过专用能力接口访问状态和命令，每个接口只声明使用的成员，不保存完整战场宿主。旧系统构造器支持场景参数，但立即转换成对应能力接口。表现组件通过 `presentation/battle/battle_access.gd` 的显式只读字段与命令方法工作，不保留完整战场场景；悬停文字是该界面契约唯一可写字段。

## 3. 组合模块

| 模块 | 职责 |
|---|---|
| `simulation/battle_world.gd` | 无场景依赖的模拟服务图，供正常战场与读档候选共用 |
| `app/battle_commands.gd` | 稳定的具名命令端口；方法直接调用弱引用提供者，世界切换时端口对象身份保持不变 |
| `simulation/battle_state.gd` | 唯一可写战斗状态；普通 RefCounted，不继承场景 |
| `app/battle_scene_state.gd` | 场景拥有的表现节点和存档服务 |
| `app/battle/bootstrap.gd` | 关卡装配、规则装载、开局与开发参数 |
| `app/battle/scene_controller.gd` | 帧投递、输入、场景退出与表现协调 |
| `simulation/battle/battle_simulation.gd` | 固定 tick 执行顺序、实体清理与摘要 |
| `simulation/battle/` | 实体工厂、空间索引、交互路径、移动、战斗、建造、生产、武将、能力、命令、战役 |
| `simulation/ports/` | 按职责声明的状态访问与函数依赖；场景退出时释放回调 |
| `simulation/navigation/` | 导航状态、网格占格、路径查询与城门 |
| `simulation/systems/ai.gd` | AI 调度、快照和稳定外部接口 |
| `simulation/systems/ai_decisions.gd` | AI 建造、训练、研究与战术决策 |
| `presentation/battle/components/` | HUD 创建与布局、命令模型与动作、输入、选择信息、相机、单位外观、世界图层 |
| `presentation/menu/` | 菜单控制器、样式、关卡选择、势力选择与自动化驱动 |
| `presentation/audio/sfx.gd` | 音效播放；随机数与模拟分离 |
| `app/saves/` | 快照字段、完整校验、候选世界恢复与提交 |
| `testing/` | 随候选包提供的自检套件；由原 `--selftest` 参数分派 |

科技和武将使用组合服务；模拟状态由 `simulation/battle_state.gd` 持有，科技服务在 `simulation/battle/technology.gd`，不保留按旧资源路径命名的兼容脚本。场景同名方法仅保留仍有外部调用的转发。

组合根通过 `composition_contract.gd` 显式连接领域提供者；端口声明 `CONTRACTS` 并直接调用具名方法，不建立平铺方法表。不同提供者可拥有同名方法，由端口明确区分。缺失提供者、缺失方法或过期弱引用属于组合错误：统一报错并请求退出码 1，当前包装方法安全返回；正式包不依赖 assert。反射注册、`_fn_*` Callable 字段和 `capability_links` 均已删除。

静态契约从服务图、真实端口和表现命令清单检查依赖；引擎侧 `dump_composition.gd` 输出实际验证的四组具名提供者契约，由 `registry_check.mjs --runtime-log` 消费。单挑目标校验、接受与伤害均在模拟层；应用层只播放已经确定结果的影片；模拟层只发出结果数据和整数票据，应用层校验世界身份后一次性结算，读档或退出使旧票据失效。

## 4. 数据所有权

- 单位是 Dictionary；稳定 `uid` 贯穿选择、编组、存档、AI 槽位、任务与引用。
- 单位不保存 `spr`、`skin`、`diamond`、`hbar` 等节点句柄。表现层按 UID 管理节点，通过 `view.unit_nodes(unit)` 查询，销毁与读档时统一释放并重建。
- 模拟状态只有一个所有者。主场景和命令端口是稳定访问入口。读档切换完整候选世界，状态和子系统对象随世界替换；应用控制器通过稳定入口读取当前世界，不持有旧状态。
- 占格、目标分桶和形状缓存只由模拟状态决定；出生、移动、死亡、装载、下船时同步维护。
- 协作组件的能力连接在关闭战场时解除；导航能力使用弱引用，独立导航对象可直接释放。

## 5. 数据流

```text
输入 → 界面消费 → 场景交互 → 命令队列
     → 校验与领域操作 → 固定 tick 模拟
     → 同步外观/声音事件 → 表现刷新
```

命令队列保留逐帧派发、64 槽容量和原顺序。应用层的子节点驱动队列；停用战场自身的 `_process` 不会停用队列。显式 `player_commands.set_process(false)` 可停用自动派发，手动 `pump()` 继续可用。

## 6. 固定步长

```
sim_acc += 真实帧时间
while sim_acc >= 速度周期 且 本帧步数 < 5:
    sim_acc -= 速度周期
    _sim_step(1/30 秒)
```

- 速度周期保留原作约定的 100/50/30/20 ms，只影响投递频率，不改变单步增量。以固定步长 1/30 秒计算，模拟时间相对墙钟时间的倍率分别为 1/3、2/3、10/9、5/3；默认“快”档为 10/9 倍，不定义为实时 1 倍。
- 单帧最多补 5 步，剩余时间保留到下一帧，不丢弃。
- 渲染帧率、相机、HUD 不参与模拟结算。
- 相同初始状态与命令序列在同一随机数状态下得到相同结果；测试与自检固定随机种子。

## 7. 存档服务

`Game` 负责文件格式、槽位与原子写。世界恢复按以下顺序进行：

1. 校验内容版本、字段、UID、引用与各子系统快照；
2. 使用同一纯模拟服务图创建 RefCounted 候选，不实例化 `main.tscn`，恢复实体、引用、科技、载员、视野与导航；
3. 候选全部成功后暂换世界并暂存新单位节点；显示验证成功才释放旧世界和旧节点，失败则恢复原世界及原节点；
4. 清理候选服务与旧节点。

验证或候选恢复失败时保留原世界与选择。地图定义为深层只读数据；会话开关由独立 `session_state` 持有，界面字段由场景持有，空间索引按世界重建。`simulation/battle_state_fields.gd` 显式登记字段策略，新增字段未登记即拒绝读档；提交不再逐字段搬运或重绑模拟服务 host。保存和恢复共用 `app/saves/snapshot_fields.gd` 的字段清单；动作计时字段由对应计时模块恢复。存档版本与旧档迁移口径保持不变，详见[存档与兼容](16-save-compat.md)。

v1–v3 先在候选中应用旧格式并规范化、验证为内部快照，再走同一世界交换事务；v4–v8 共用完整候选恢复。存档格式版本保持 8。

## 8. 地形与纹理

| 项 | 规则 |
|---|---|
| 地形来源 | 34 张地图的高清分块，运行时按视口加载 |
| 分块 | 世界尺寸 256×256；纹理 LOD 4 / 2 / 1（1024 / 512 / 256 像素） |
| 预取 | 可视范围外扩 256 世界像素 |
| 驻留预算 | 384 MiB（按 RGBA 解码字节估算） |
| 超预算 | 自动降 LOD；仍超则报错并停止加载 |
| 传输格式 | 发布包使用 JPEG 编码的 `.bin`，运行时解码上传 |
| 纹理声明 | 正式高清缺失为错误；显式原图回退缺失为警告；开发环境可直接解码 PNG |
| 纹理缓存 | 图集按路径缓存；地形分块不进入共享缓存，移出视口即释放 |

## 9. 性能预算

以最大地图的实际视口、全图取景与反复平移为基准：

| 指标 | 门槛 |
|---|---:|
| 开局进入战场 | ≤ 15 秒 |
| 单次地形更新 | ≤ 5 秒 |
| 地形纹理驻留 | ≤ 384 MiB |
| 全部渲染纹理峰值 | ≤ 768 MiB |
| Godot 静态内存峰值 | ≤ 1.5 GiB |
| 同时实体 | 每方 ≤ 200 |
| 800 单位微基准（占格索引） | P95 ≤ 100 ms |
| 完整战场 200 机动单位 P95 | ≤ 500 ms |
| 完整战场 660 机动单位压力 P95 | ≤ 1200 ms |
| 实际窗口 FPS | 标准 ≥ 60，压力 ≥ 30 |
| 进程峰值工作集 | 标准 ≤ 2.5 GiB，压力 ≤ 3.5 GiB |
| Godot 视频内存 | 标准 ≤ 1.25 GiB，压力 ≤ 1.5 GiB |

- 完整战场门槛以 i7-8700、64 GB、Quadro P4000 8 GB、1920×1080 为参考机，由 `tools/bench_full_battle.ps1` 复测；它覆盖 AI、寻路、战斗、弹体、采集、施工、渲染与流式地形，微基准只覆盖占格索引。
- 进程工作集另计字体、视频、引擎与驱动开销；地形预算不等于进程总内存。
- 上述为开发机回归门槛，不是最低配置承诺。

## 10. 线程与并发

- 运行时模拟与渲染都在主线程；不做多线程模拟。
- 构建阶段的资源导入与地形分块编译使用独立进程/多 worker，不进入运行时。
- 同一建筑的生产、研究、出售互斥；不同建筑可并行，但都在主线程按 tick 推进。

## 12. 验收要点

- 无视图模式可完整跑完模拟，且不创建渲染节点。
- 相同 tick 数下，不同速度与渲染帧率得到相同摘要。
- 地形驻留不超预算；超限时降 LOD 而不是崩溃。
- 模拟模块不引用 `presentation/`；表现模块不写生命、资源与生产。
- 新存档字段必须同时进入校验与恢复，否则拒绝加载。

指令队列发出 `commands_applied`，由宿主连接表现层刷新；队列不直接调用表现层。战斗使用独立 `simulation_rng`，与音效随机序列分离，`rngState` 以十进制字符串进入快照；旧档缺少该字段时沿用关卡初始化序列。旧整数 world digest 继续用于历史基线，子系统 SHA-256 由 `state_digest` 模块统一计算。

城门附近的烘焙墙体按列复用现有纹理，在墙脚深度绘制前景遮挡，门洞继续使用相同开口材质。地面选框与插值后的脚底使用相同深度，避免遮挡恢复时选框浮在城墙上。遮挡属于表现层，不修改通行网格与墙体像素。

## 13. 结构门禁

`node tools/architecture_check.mjs` 检查直接及传递分层依赖、模拟节点所有权、入口和模块大小。三个入口预算分别为 250、500、400 行，其余运行脚本为 600 行。迁移保留的长函数在 `tools/inputs/architecture_limits.json` 中逐项记录；新增超过 80 行的函数或已有函数超出记录预算时必须重新评审。

同一文件还检查三条与"可无视图运行"直接相关的规则：

- `simulation/` 不得出现 `get_node(`、`: Node` 类型标注或 `/root/` 路径——模拟必须能在没有场景树时运行；
- `app/` 不得消费 `simulation_rng`（`randi`/`randf`）——玩法随机性只能落在 `simulation/`，否则 headless 摘要覆盖不到；读写 `rngState` 用于存档不在此列；
- `presentation/` 不得直接 `preload("res://simulation/systems/...")`，只能经端口或 `battle_config` 的公共常量。

引入规则时已存在的违规记在同文件的 `violations` 数组（`<文件>::<规则>`），逐条列明并保持让检查通过；新增违规直接失败，修好后应删除对应条目，因此该列表只能变短。

`node tools/registry_check.mjs` 直接读取源码中的显式端口 `CONTRACTS`，逐条核实提供者方法、包装方法的失效保护、领域命令调用及回调引用，并检查所有端口均在覆盖范围内。组成清单仅登记服务路径和端口所属宿主，不复制方法契约；新增或修改方法无需手工同步第二份清单。守卫允许同一行或多行排版，注释不能替代实际守卫，调用必须位于判空返回之后。清单与组合根的实际工厂声明交叉校验；`--runtime-log` 再严格比较四个根的服务集合及脚本路径。状态代理仅暴露各状态类登记的 `PROXY_FIELDS`，门禁逐项核对声明，未登记的写入返回失败。上述检查由 `tools/ci_lightweight.mjs` 和 `contracts` 工作流执行。

`battle_commands` 只持有经济、军事、科技、指令、世界及会话六个领域端口，不提供扁平转发。组合根一次连接所有命令端口，并汇总缺失诊断；读档候选复用相同工厂，仅连接模拟领域。表现层从读模型读取状态，经 `commands.<领域>.<方法>` 发命令或绑定按钮回调。

跨服务弱引用的失效语义为：记录契约诊断、请求退出码 1、当前包装方法立即返回类型对应的空结果。`SceneTree.quit()` 不终止当前调用栈，因此每个包装方法都显式判空，禁止随后解引用。调用方在本帧仍可能继续执行，日志明确标注 `current frame continues with defaults`；该结果仅用于退出期间安全退栈，不代表业务成功或游戏恢复。负向测试调用生产包装方法，验证后续探针仍可执行、最终退出码为 1 且没有二次脚本错误。候选验证为每张地图及每项基线启动独立进程，某一项的退出码不会误记为另一项。

战斗读模型作为战斗节点子树的一部分，与场景状态和领域命令端口共享生命周期，持有后二者的强引用；对 Node 数据宿主使用受检弱引用。整体换世界时，稳定宿主仍读取新世界；退出后继续访问读模型会使用相同契约诊断，不裸解引用已释放宿主。

未知视觉或音效请求单独处理：调试引擎记录契约错误并请求退出；正式引擎按 `OS.is_debug_build()` 选择警告和丢弃，仅首次遇到某动词时报警，并累计次数，在战役结束或退出时汇总一次。该计数属于表现会话，不进入存档和模拟摘要，不改变伤害、RNG 或结算。依赖端口失效始终保持非零退出，不适用此表现事件降级策略。

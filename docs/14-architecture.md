# 14 技术架构

> 本章定义运行时分层、模块职责、数据流、确定性与性能预算。数据字段见[数据规格](15-data-spec.md)，存档见[存档与兼容](16-save-compat.md)。

## 1. 运行形态

| 项 | 值 |
|---|---|
| 引擎 | Godot 4.7.2，GL Compatibility 渲染器 |
| 语言 | GDScript |
| 主场景 | `menu.tscn` |

## 2. 分层与依赖

| 层 | 目录 | 职责 |
|---|---|---|
| 场景装配 | `main.gd`、`menu.gd`、`presentation/battle/view/battle_presentation_factory.gd` | 生命周期、组件连接与表现构造边界 |
| 应用服务 | `app/` | 世界加载、存档事务、场景节点与用户存储 |
| 模拟 | `simulation/` | 独立状态、命令、规则、固定 tick、导航与 AI |
| 表现 | `presentation/` | 节点、HUD、菜单、相机、动画、音视频 |
| 数据 | `data/`、`media/`、`art/` | 稳定数据格式与素材 |
| 工具 | `tools/` | 导出、构建、回归、验证与发布 |

模拟不引用应用或表现模块，不持有场景节点。场景通过 `battle_effects` 同步接收外观与声音请求；有视图与无视图使用相同模拟数据。跨层调用使用显式能力接口。领域服务在模拟层共享 BattleState，各自负责所属领域的写入。表现组件通过 `app/read_models/battle_queries.gd` 读取标量，以及通过 `unit`、`map`、`commands`、`status` 读取各领域投影，不保留完整战场场景。单位、选择、资源、视野、时钟和效果通过冻结值投影、标量查询或独立字节缓冲读取；投影按世界身份、领域版本和视口复用，禁止逐帧深拷贝完整世界。配置容器也不暴露可变引用。存档服务不向表现层暴露。P7 的业务变更由字段所属领域的具名操作写入，包括单位位置、选择、世界装配和资源余额。跨域调用只开放所需的具体接口文件。

| `app/battle/commands/battle_actions.gd`、`app/battle/session/session_actions.gd`、`app/read_models/battle_queries.gd` | 提交玩家意图、办理会话操作、读取显示投影 |
| `simulation/state/battle_state.gd` | 共享权威状态容器；普通 RefCounted，不继承场景；字段业务写入者见 `tools/inputs/battle_state_ownership.json` |
| `app/battle/runtime/battle_scene_state.gd` | 场景拥有的表现节点和存档服务 |
| `app/battle/startup/bootstrap.gd` | 关卡装配、应用已冻结规则、开局与开发参数 |
| `app/battle/runtime/scene_controller.gd` | 帧投递、输入、场景退出与表现协调 |
| `simulation/world/battle_simulation.gd` | 固定 tick 执行顺序、实体清理与摘要 |
| `simulation/<领域>/` | `units`、`movement`、`navigation`、`combat`、`economy`、`construction`、`production`、`transport`、`technology`、`officers`、`commands`、`ai`、`cheats`、`scenario`、`visibility`、`definitions`、`diagnostics` |
| `simulation/navigation/` | 导航状态、网格占格、路径查询与城门 |
| `simulation/ai/ai.gd` | AI 调度、快照和稳定外部接口 |
| `simulation/ai/ai_decisions.gd` | AI 建造、训练、研究与战术决策 |
| `presentation/battle/{view,camera,input,hud,command,units,world,resources,effects}/` | 视图、相机、输入、HUD、命令面板、单位外观、世界图层、资源与特效 |
| `presentation/menu/`、`testing/automation/` | 菜单控制器、样式、关卡选择、势力选择；自动化 harness 只在验收开关下加载 |
| `presentation/audio/sfx.gd`、`presentation/shell/` | 音效播放；常驻 PresentationHost 与软件光标 |

科技和武将使用组合服务；模拟状态由 `simulation/state/battle_state.gd` 持有，科技服务在 `simulation/technology/technology.gd`，不保留按旧资源路径命名的兼容脚本。场景同名方法仅保留仍有外部调用的转发。

战场组合根持有具名服务，并在初始化时连接协作者。启动装配失败以退出码 1 终止，候选装配失败返回读档错误。

模拟在执行单挑命令的 tick 内完成接受判定、抽样和伤害写入，再发送影片所需的显示值。影片结束和跳过只影响表现。

### 3.1 规则启动边界

`Game._init` 在主场景对象构造前调用 `app/rules/rule_loader.gd`，一次读取兵种、生产、建筑、状态调参、武将、成长、指令分型、任务、原生签名、科技、兵种角色和容量参数十二个目录。`rule_contract.gd` 校验被消费的字段；任务语法由 `scenario_contract.gd` 校验；状态持续时间受 Unit Schema 上限约束。读取、解析和校验错误按目录汇总，任一失败时拒绝发布并以非零退出码终止启动。

`simulation/definitions/rule_catalog.gd` 接收整批目录，复制后递归冻结，仅发布一次。所有世界和候选世界共享同一份纯值规则，不重新读取文件。武将成长与关卡单位定义在世界创建时复制为独立可写数据；状态查询、移动倍率和视野查询直接读取冻结规则，不在 tick 中复制容器。规则身份也基于已安装目录计算，运行期间不热加载目录。

科技行、解锁线、完成结果和研究周期由 `tech.json` 定义；角色集合与科技档位由 `unit_roles.json` 定义；`balance.json` 定义实体、主将、编队和运输容量，以及采集的周期、轮询、载量、提取量和交付建筑，休息、修理、施工的费用与进度，计谋成本和射程。查询模块只读冻结目录，JSON 整数标识在发布前规范化为 int，避免成员查找的 Variant 类型差异。目录间的兵种和武将引用在整批校验时检查。人口准入保留存活实体、排队名额和各入口原有时序。

原生扩展发现、加载和签名验证由 `app/rules/native_backend.gd` 在启动时完成。缺少可选扩展使用脚本实现；存在但加载失败或不兼容的后端拒绝启动。`math_kernel.get_kernel()` 仅查询已安装提供者，不重试探测。模拟层禁止文件、目录、动态资源加载和 JSON 解析；脚本 `preload` 声明仍可用于组合依赖。

模拟中的墙钟采样集中在 `ProfileClock`，生产默认关闭；明确的剖析或性能测量开关才启用采样。功能计数保留，计时结果不进入持久化状态。基准工具为逻辑和实际帧驱动测量显式开启计时，渲染预热期间关闭采样并验证模拟状态不变。

### 3.2 应用生命周期与暂停

应用控制器只接收场景服务和场景节点，状态通过当前节点查询，不接收随后忽略或可能过期的 BattleState 参数。普通世界与候选世界仍分别使用领域和行为模块所需的构造协议，组合根拥有创建权。

`Game` 拥有唯一的 `PauseStack` 节点，只有它写入 `SceneTree.paused`。菜单、任务简报、影片和结算以自己的节点申请暂停令牌；关闭只释放自身令牌，所有者退出场景时自动释放。令牌清理不恢复缓存的全局布尔值，非顶层模态不消费键盘关闭事件。读档事务使用独立令牌，失败时释放事务令牌并维持原有暂停。菜单在成功后关闭其令牌。

关卡选择读取生成的 `level_index.json`，目录校验后缓存冻结元数据和战役顺序；查询不打开完整地图。场景导航在切换调用期间准备会话选择，失败恢复地图、待加载槽位和错误信息；失败返回菜单的错误说明保留到菜单展示。构建导出关卡后生成索引，复用数据的构建必须通过索引新鲜度检查。

## 4. 数据所有权

- 单位是 Dictionary；稳定 `uid` 贯穿选择、编组、存档、AI 槽位、任务与引用。
- 单位不保存 `spr`、`skin`、`diamond`、`hbar` 等节点句柄。表现层按 UID 管理节点，通过 `view.unit_nodes(unit)` 查询，销毁与读档时统一释放并重建。
- 模拟状态只有一个所有者。主场景和命令端口是稳定访问入口。读档切换完整候选世界，状态和子系统对象随世界替换；应用控制器通过稳定入口读取当前世界，不持有旧状态。
- 占格、目标分桶和形状缓存只由模拟状态决定；出生、移动、死亡、装载、下船时同步维护。
- 协作组件的能力连接在关闭战场时解除；导航能力使用弱引用，独立导航对象可直接释放。

## 5. 数据流

| 职责 | 数据与行为 |
|---|---|
| Command | 应用入口绑定当前世界。单次输入记录来源、势力、有序执行者 UID、命令种类、目标引用或坐标、参数、应用 tick 和序号。 |
| Order | 在领域入口重新校验角色、目标、前置和费用。沿用单位任务字段以及生产、研究队列。 |
| Behavior | 固定 tick 推进移动、交战、采集、施工等任务，处理完成、取消、脱离和失效。 |
| State | BattleWorld 持有模拟数据与持久状态。拖拽、选择与瞄准模式由会话持有。 |
| Rule | 冻结的规则目录提供可调值和资格参数，领域服务定义执行和结算顺序。 |

玩家命令占用最多 64 个执行者槽位，在下一逻辑 tick 的命令相位按入队次序应用。AI 与托管从各自的决策相位通过同型命令调用共享的领域方法。右键情境指令在提交时确定意图，目标在应用时按 UID 或饰物格解析。暂停菜单和关窗优先等待已提交指令结算，暂停阻止推进时保存返回可重试错误。

## 6. 固定步长

```
sim_acc += 真实帧时间
while sim_acc >= 速度周期 且 本帧步数 < 5:
    sim_acc -= 速度周期
    _sim_step(1/30 秒)
```

- 速度周期保留原作约定的 100/50/30/20 ms，只影响投递频率，不改变单步增量。以固定步长 1/30 秒计算，模拟时间相对墙钟时间的倍率分别为 1/3、2/3、10/9、5/3；默认“快”档为 10/9 倍，不定义为实时 1 倍。
- 单帧最多补 5 步，剩余时间保留到下一帧，不丢弃。
- 渲染帧率、相机、HUD 不参与模拟结算。
- 相同初始状态和带执行 tick 的命令序列在同一随机数状态下得到相同结果；测试与自检固定随机种子。

## 7. 存档服务

`Game` 保留格式编解码、场景生命周期和既有 autoload API。SaveRepository 拥有文件地址、写事务，SlotCatalog 拥有元数据缓存，CampaignSession 拥有战役选择与待加载状态。写入成功通过事件使槽位缓存失效，服务可脱离 Game 单独测试。世界恢复按以下顺序进行：

1. 读取槽位及来源，按目标地图准备数据，校验内容身份、单位关系和子系统字段。
2. 使用场景无关的候选 BattleWorld 恢复实体、科技、载员、视野与导航。
3. 在现有战场场景内暂存单位节点。跨图先释放旧地形分块，再准备目标地形、更新相机与小地图。
4. 成功时提交世界和会话地图。失败时恢复原世界、单位节点、相机与地形。

验证或候选恢复失败时保留原世界与选择。地图定义为深层只读数据；会话开关由独立 `session_state` 持有，界面字段由场景持有，空间索引按世界重建。`simulation/state/battle_state_fields.gd` 显式登记字段策略，新增字段未登记会拒绝保存与读档；提交不再逐字段搬运或重绑模拟服务 host。`simulation/units/unit_schema.gd` 是单位字段的唯一登记处，包含类型、默认值、持久化、派生策略和恢复分组；snapshot、validator、restorer、timers、action clock、locomotion 由它取得字段定义，关系引用按 Schema 的 codec 和键名编解码。工厂和常见单位写入的静态检查，加上真实单位与逐字段反射回归，防止字段静默遗漏。存档只接受当前格式，详见[存档与兼容](16-save-compat.md)。

反馈文本、输入事件计数、阵营显示开关、拖拽与框选坐标属于 `battle_scene_state`，不进入候选世界；成功读档清空待选命令与拖拽/反馈瞬态，失败保留原会话。正在等待目标的模式和选择由 `session_state` 管理。

存档格式为 v9，读取器没有旧版本迁移分支。规则与地图身份必须精确匹配。

## 8. 地形与纹理

| 项 | 规则 |
|---|---|
| 地形来源 | 34 张地图的高清分块，运行时按视口加载 |
| 分块 | 世界尺寸 256×256；纹理 LOD 4 / 2 / 1（1024 / 512 / 256 像素） |
| 预取 | 可视范围外扩 256 世界像素 |
| 驻留预算 | 384 MiB（按 RGBA 解码字节估算） |
| 超预算 | 自动降 LOD；仍超则报错并停止加载 |
| 传输格式 | 发布包使用 JPEG 编码的 `.bin`，运行时解码上传 |
| 纹理声明 | 正式高清缺失为错误；显式原图回退缺失为警告；开发环境可直接解码 PNG |
| 纹理缓存 | 图集按路径缓存；地形分块不进入共享缓存，移出视口即释放 |

## 9. 性能预算

以最大地图的实际视口、全图取景与反复平移为基准：

| 指标 | 门槛 |
|---|---:|
| 开局进入战场 | ≤ 15 秒 |
| 单次地形更新 | ≤ 5 秒 |
| 地形纹理驻留 | ≤ 384 MiB |
| 全部渲染纹理峰值 | ≤ 768 MiB |
| Godot 静态内存峰值 | ≤ 1.5 GiB |
| 同时实体 | 每方 ≤ 200 |
| 800 单位微基准（占格索引） | P95 ≤ 100 ms |
| 完整战场 200 机动单位 P95 | ≤ 500 ms |
| 完整战场 660 机动单位压力 P95 | ≤ 1200 ms |
| 完整战场实时 tick P95 | ≤ 当前逻辑周期（最快档 30 ms） |
| 实际窗口 FPS | 标准 ≥ 60，压力 ≥ 30 |
| 进程峰值工作集 | 标准 ≤ 2.5 GiB，压力 ≤ 3.5 GiB |
| Godot 视频内存 | 标准 ≤ 1.25 GiB，压力 ≤ 1.5 GiB |

- 完整战场门槛以 i7-8700、64 GB、Quadro P4000 8 GB、1920×1080 为参考机，由 `tools/bench_full_battle.ps1` 默认使用当前正式 release 模板与完整 PCK 复测；源码诊断必须显式加 `-DeveloperSource`，不作为验收；它覆盖 AI、寻路、战斗、弹体、采集、施工、渲染与流式地形，微基准只覆盖占格索引。
- 进程工作集另计字体、视频、引擎与驱动开销；地形预算不等于进程总内存。
- 上述为开发机回归门槛，不是最低配置承诺。

## 10. 线程与并发

- 运行时模拟与渲染都在主线程；不做多线程模拟。
- 构建阶段的资源导入与地形分块编译使用独立进程/多 worker，不进入运行时。
- 同一建筑的生产、研究、出售互斥；不同建筑可并行，但都在主线程按 tick 推进。

## 12. 验收要点

- 无视图模式可完整跑完模拟，且不创建渲染节点。
- 相同 tick 数下，不同速度与渲染帧率得到相同摘要。
- 地形驻留不超预算；超限时降 LOD 而不是崩溃。
- 模拟模块不引用 `presentation/`；表现模块不写生命、资源与生产。
- 新存档字段必须同时进入校验与恢复，否则拒绝加载。

指令队列发出 `commands_applied`，由宿主连接表现层刷新；队列不直接调用表现层。战斗使用独立 `simulation_rng`，与音效随机序列分离，`rngState` 以十进制字符串进入快照；当前格式要求该字段存在。旧整数 world digest 继续用于历史基线，子系统 SHA-256 由 `state_digest` 模块统一计算。

城门附近的烘焙墙体按列复用现有纹理，在墙脚深度绘制前景遮挡，门洞继续使用相同开口材质。地面选框与插值后的脚底使用相同深度，避免遮挡恢复时选框浮在城墙上。遮挡属于表现层，不修改通行网格与墙体像素。

## 13. 结构门禁

`node tools/architecture_check.mjs` 检查直接及传递分层依赖、模拟节点所有权、入口和模块大小。传递依赖同时跟随 `preload`/`load` 与 `extends "res://…"`。三个入口预算分别为 250、500、400 行，其余运行脚本为 600 行。迁移保留的长函数在 `tools/inputs/architecture_limits.json` 中逐项记录；新增超过 80 行的函数或已有函数超出记录预算时必须重新评审。

同一文件还检查三条与"可无视图运行"直接相关的规则：

- `simulation/` 不得出现 `get_node(`、`: Node` 类型标注或 `/root/` 路径——模拟必须能在没有场景树时运行；
- `app/` 不得消费 `simulation_rng`（`randi`/`randf`）——玩法随机性只能落在 `simulation/`，否则 headless 摘要覆盖不到；读写 `rngState` 用于存档不在此列；
- `presentation/` 不得直接 `preload("res://simulation/systems/...")`，只能经 `battle_queries`/`battle_actions` 或 `battle_config` 的公共常量。

`extends Object` 的脚本必须由一个含 `_owned_services()`、`_owned_components()` 或 `free()` 的装配点持有——Object 没有引用计数兜底，漏登记即永久泄漏。

引入规则时已存在的违规记在同文件的 `violations` 数组（`<文件>::<规则>`），逐条列明并保持让检查通过；新增违规直接失败，修好后应删除对应条目，因此该列表只能变短。

`node tools/registry_check.mjs` 核对组合根工厂、直接协作者的方法和状态字段登记。工厂断言要求具名赋值与 `preload("res://<文件>")` 或同名常量精确对应，短名不得靠子串命中。另解析 `app/`、`presentation/` 中的 `world.<服务>.<成员>(...)` 调用，成员必须在组成清单登记的服务脚本里存在。引擎侧 `dump_composition.gd` 提供四个组合根的实际装配记录。

清单与组合根的实际工厂声明交叉校验；`--runtime-log` 严格比较四个根的服务集合及脚本路径。状态代理仅暴露各状态类登记的 `PROXY_FIELDS`，未登记的写入返回失败。上述检查由 `tools/ci_lightweight.mjs` 和 `contracts` 工作流执行。

领域行为和界面组件由各自的组合根独占并显式释放。它们使用 Godot Object 的非拥有引用直接互调，状态、查询缓存和需要独立生命周期的服务使用 RefCounted。世界拥有经济、导航、命令和 AI 等服务，并负责原生回调和导航查询的释放。

表现层通过 BattleQueries 查询投影，通过 BattleActions 操作战场，通过 SessionActions 管理暂停和存档。相机、音频和 HUD 节点归视图上下文持有。菜单自动化驱动按验收命令行参数加载。

装配错误在创建阶段报告组件与缺失依赖，场景启动失败以非零码退出。交互中失效的单位、过期的世界身份和无效槽位由对应操作返回业务结果。读模型以弱引用持有宿主：宿主释放后每条查询返回自身类型的空值并报告一次契约失败，关闭与换世界期间不得解引用已释放节点。

战斗读模型和操作入口由场景持有。候选视图准备使用独立读模型，提交后稳定入口读取新世界。

未知视觉或音效请求单独处理：调试引擎记录契约错误并请求退出；正式引擎按 `OS.is_debug_build()` 选择警告和丢弃，仅首次遇到某动词时报警，并累计次数，在战役结束或退出时汇总一次。该计数属于表现会话，不进入存档和模拟摘要，不改变伤害、RNG 或结算。依赖端口失效始终保持非零退出，不适用此表现事件降级策略。


## 14. 压力场景的计算后端与派生缓存

固定 tick、30 ms 最快档周期、每帧最多五步追帧及欠账保留策略不变。Windows 使用 `simulation/native/math_kernel.gd` 装配的可选 RefCounted 计算后端，Linux 与不可用的平台运行保留的脚本算法。后端只接收当前调用所需的数据，不持有世界、场景树、表现对象或 RNG；路径选择、伤害、命令与实体生命周期仍由原有模拟领域按顺序结算。脚本与原生路径必须逐字段一致。

接触缓存按双方精确坐标、UID、兵种、射程与导航版本失效；索引和派生导航图属于当前世界，切换世界后重新建立。视野批量更新保留源处理顺序、探索记忆和修订语义。缓存与剖析计数不进入存档。

生产代码不启用计时剖析。完整基准的 `-ProfileUnits` 同时报告世界阶段与单位阶段；嵌套计时不能直接相加。正式 FPS 阶段关闭剖析，诊断运行不计入验收。命令与验收口径见[压力场景与后端对照](19-testing.md#压力场景与后端对照)。

资源查询索引属于行为模块，按导航对象身份、几何修订和资源修订失效。资源片缓存以资源种类和点击起点为根，保留 BFS 顺序和候选顺序，最多保留 16 个根；内容仅有格坐标、键和冻结值容器。动态单位占用与城门权限在每次查询时重新判断。一批候选共享一次临时导航避让，成功、失败和候选拒绝都恢复原标志；已禁用的点不重复切换。点击索引按屏幕桶返回源数组索引，等距时仍保留原始顺序。

施工队归属和成员索引仅在一次同步决策内使用。每次决策从当前单位表构造，以保持招募、死亡、换归属和上下船后立即可见；不依赖所有 Dictionary 写入都维护一份长期缓存。成员校验、人数上限与可施工兵种由同一查询实现。

单位 tick 先执行共同前置条件，再派发独立状态处理器，最后推进动画。交付等待保留提前返回语义，附着、工地、状态效果和卸载计时的顺序保持固定。行军的堵塞终点搜索每次单位更新最多尝试六条替代路线，路径层含避让失败后的普通查询回退时最多十二次查询；未完成搜索保留终点和已保存游标，下次更新继续，完成整圈后才计一次失败。正常移动或新命令清除游标。


## 组合根封装与读模型试点

正常场景和候选世界由 `BattleWorld._init` 统一构造全部领域服务并经 `bind_dependencies(world)` 绑定 `_dep_` 具名协作者，装配一致性由 `validate_services` 走 `composition_contract.wire` 校验，缺项即以非零退出终止；候选世界装配失败返回读档错误。地图实体播种通过 `World.seed_map_units` 显式入口进行。GDScript 不提供语言级私有隔离，跨层访问边界由 `architecture_check` 与 `registry_check` 门禁约束。

领域服务的 `new(world)` 与行为模块的 `new(state)` 暂时保留：前者取得窄能力，后者操作领域状态。是否统一协议属于后续架构决策，不为统一签名改变所有服务。

相机、建造预览、资源层、单位名册/选择/生产以及 visibility/clock/projectiles/fire_fields/player_commands 等读模型已迁移；表现层不再借用 units、selected、map_data、nav、trainings、decor_cells 及服务配置容器。公开接口只返回值、UID 或递归冻结的投影，不能把“返回 Dictionary”当作可写授权。其余经别名、动态键或命令返回对象继续传递的引用仍需人工审查。

`tools/port_inventory.mjs` 检查旧提供者字段、作用域借用以及依赖适配器是否再次进入运行时代码。


### 建造预览的值投影

`build_preview.gd` 与相机组件一样，不再访问 `units/selected/map_data/nav`。BattleQueries 的预览接口只返回固定字段的占格、轮廓、单格多边形、位置、尺寸、材质尺度和校验结果；每个容器递归冻结，数据中没有单位、导航、服务或 Callable 引用。

只读 Dictionary 不能使其中的 Packed 数组变为只读，所以公开投影使用冻结的普通值数组。组件在缓存失效时创建自己拥有的 Packed 绘制缓冲，逐帧复用。投影显式选取少量字段并冻结新容器，不深拷贝整个 units、selected 或 map_data。

缓存键包含世界和导航实例身份、tick、导航版本、格位、单位数、选择 UID、资源、终局/归属/建造开关与模板尺寸。世界交换即使所有逻辑数值相同也必须失效；成功加载、失败回滚和恢复后立即重新进入建造模式均有回归。缓存沿用单位运动随模拟 tick、结构变化随导航版本的更新约定，不充当任意直接字典修改的通用追踪器。

剩余字面量访问由 `tools/battle_access_inventory.mjs` 维护，扫描结果是调用位置清单，不是接收者类型证明；别名、动态键及命令返回的字典仍需人工审查。


### 资源层值投影与生命周期

`battle_resources.gd` 不再保存 entries，也不读取 map_data、nav 或 decor_cells。BattleQueries 提供资源层的值键和可见描述数组，每个描述仅包含 index、anchor、phase；新建容器递归冻结，结果不含资源字典、地图、导航、Object、Callable 或可变 Packed 数组。decor_cells 的旧借用 getter 已从 BattleQueries 删除。

资源层按世界身份、导航身份、resource_revision、导航几何版本和视口 Rect2 缓存。逐帧仅比较常量大小的值键；键变化后扫描 decor，只构造可见描述，不深拷贝整个地图或资源记录。普通阻挡版本变化不影响资源画法，不触发重扫；资源定义的直接修改必须提升资源版本或更换世界。资源片连通区与点击命中分别由 `simulation/economy/resource_index.gd` 的缓存/空间桶服务，资源层投影不持有该索引或旧世界。

精灵、纹理和图集 frame 元数据由表现层管理。即使 index 和 phase 相同，几何或世界变化后也更新精灵位置；phase 5 按既有图集声明跳过并移除旧精灵。实际交换回滚和读档、所有非身份键值相同的替换、保留旧投影时释放旧世界/导航均由回归覆盖。


### 缺失表现资源的显式恢复

HUD skin 对缺失的面板、横幅、资源图标和左侧控件纹理返回 null，裁片前检查源纹理和图像；顶栏母版缺失时使用已有平色 HUD 布局。minimap 对目录缺失、损坏、条目缺失或不可解码图像记录错误并建立占位背景，继续建立雾、单位标记和镜头导航层，不依赖正式构建会剥离的 assert。

地形流式加载先确认最低 LOD 的可见工作集能进入驻留预算，失败清空待加载目标与队列。实际安装按声明字节与解码 RGBA 估算的较大值记账，在 GPU 纹理创建前拒绝超限。已有后台 CPU 任务会完成并丢弃，不再安装；视口/预算恢复合法后可重新请求。该保护不认证全部 CPU 临时内存或正式 FPS 指标。

单位移除入口先拒绝负索引和越界索引，之后才操作索引、占地或选择；解散和施工回滚按 UID 加对象身份定位当前实体，避免 Dictionary 深比较把旧对象当作现世界成员。

### 单位、选择与生产读值

BattleQueries 退役 units、selected、map_data、nav、decor_cells、trainings 六类借用 getter。单位名册、选择面板、生产、工作、悬停和指针查询只返回所需的标量、Vector 值及递归冻结容器；图集元数据单独复制、冻结，在同一世界内作为静态定义复用。公开模型不含单位对象、导航、服务、Callable 或可变 Packed 数组。

单位名册按世界、导航身份、几何修订、tick、成员数和视觉事件失效。可见单位再按 UID 取得渲染投影，不为隐藏单位和小地图构造全部动画字段；UID 到源数组索引的缓存只保存整数，不保存源字典。插值帧复用更新边界的值，运动采样只在 tick 边界构造必要位置。选择查询额外比较实际显示标量、武将类别与等级等字段，覆盖暂停期间的健康和选择变化。普通属性通过模拟更新或视觉事件发布，任意绕过事件的外部字典写入不属于通用追踪契约。

取消生产和施工的 UI 回调只捕获 UID、世界身份及动作种类，应用命令在入队和执行时分别校验世界身份，再解析当前实体。旧世界的相同 UID 不能取消新世界工作。投影和回调可被保留，但不能因此保留旧世界。成功交换和失败回滚均按实际世界身份重新建立投影。

存档编排使用 attach_loaded_world、finish_loaded_world、apply_loaded_unit 等表现入口；精灵、血条、历史、完成界面和弹体痕迹由视图自己维护。门禁禁止存档流程直接操作 unit_nodes/event_view/completion/end_label/projectile_view；应用启动与媒体组合的其他表现依赖仍分别治理。

借用清单 schemaVersion 4 包含十五类入口，对整个 presentation 检查属性及字面量 get/index 回退，并禁止恢复这些 getter 和深拷贝整个单位记录。零命中覆盖集合、visibility/clock/projectiles/fire_fields/player_commands 服务及建造、待定指令、任务和地形配置；别名和其他命令返回值仍需审查。相机、音频、纹理和视图节点属于表现层所有权，不等同于模拟状态投影。


### 服务与配置读边界

visibility_view 返回冻结的世界/服务身份键、尺寸及不可变字节字符串，只在修订变化时编码；渲染器自行解码并拥有图像缓冲。point_visible 与 visibility_geometry 是标量查询，渲染上下文不保存模拟可见性对象。时钟以冻结的速度、标签和周期返回，速度写入仍经命令入口。

弹体与火场查询只检查有界活动表的显示字段，变化后才构建点、方向、比例、年龄与可见标记。手动服务步进不必依赖 sim_tick 也会失效。建造选项按世界和内容签名冻结，事件和地形仅提供计数、ID 和布尔查询。缓存键不保存服务对象；相同修订与数值的替换世界仍因身份不同而重建。

玩家命令带有世界身份。成功切换后旧世界操作失效，准备失败后原有队列继续运行。

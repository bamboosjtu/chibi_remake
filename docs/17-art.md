# 17 美术规格

> 本章定义高清素材的方向、清单、目录与命名、帧契约、地形装配、阵营色、UI 与制作管线。素材权利见[权利与分发](20-legal.md)。

## 1. 方向

| 项 | 要求 |
|---|---|
| 视角 | 保持等距视角、建筑构成、世界占地与阵营标记 |
| 轮廓与配色 | 忠于原始轮廓与配色；重绘材质与细节 |
| 细节 | 清晰的木纹、布料、瓦片、土石与金属质感 |
| 背景 | 精灵透明背景；紧凑阴影，不烘焙大面积光晕 |
| 文字 | 标题、按钮、任务文字由游戏绘制，不烘焙进图片 |
| 尺寸 | 采样区域与世界尺寸分离；等比适配原可见范围并对齐底边 |
| 碰撞 | 碰撞、选择、导航与数值由模拟定义，不取自图片 |

## 2. 覆盖清单

| 类别 | 数量 | 说明 |
|---|---:|---|
| 建筑 | 27 类 | 每类一套帧表，含建造/损毁阶段 |
| 兵种 | 26 个类型定义 | 52 复用 48 的图集 |
| 武将头像 | 117 | 按稳定索引对应人物 |
| 地形组 | 14 组 | 三层地形，等距瓦片 |
| 地图 | 34 张 | 由地形组装配 |
| 单位图集 | 约 150 张 | 按兵种 × 阵营拆分 |
| UI 母版 | 10 张 | HUD 面板、匾额、资源图标、命令图标、光标等 |

- 运行帧表共 2776 个映射，显式原图回退为 0。
- 辅助切片（如文将轮廓、弓兵特殊姿态、粮食小堆）使用独立补绘，不被分页母版覆盖。
- 未被任何动画剪辑引用的源帧保留透明并记录原因，不视为漏绘。

## 3. 目录与命名

```
godot/chibi_remake/art/full/          运行素材（打包/运行时引用）
├── backgrounds/            大型画面（标题、结局等）
├── buildings/              000-atlas-v1.png（类型 ID 三位 + 版本）
├── units/<id>/             page-00-v1.png（分页动作图集）
├── officers/               000-portrait-v1.png（稳定索引 + 版本）
├── terrain/                00-atlas-v1.png（地形组 + 版本）
├── terrain_chunks/<map>/   分块与 manifest.json
├── terrain_events/         事件地形补片
├── gate_terrain/           <map>-<A>-<B>[-road].png
├── ui/                     HUD、图标、光标
├── maps/                   <map>.json 与取景图
├── manifest.json           总清单
└── team_palette.json       阵营色定义

godot/chibi_remake/art/production/    重制生产数据（随 Git 维护，不打包）
├── catalog.json            素材契约（ID、帧、锚点、来源、验收）
├── coverage.json           银行帧覆盖与交付状态
├── runtime-hd-coverage.json 运行覆盖审计
├── *-prompts*.json         提示词与批次
├── *-delivery.json         交付记录索引
├── gate-*.json             城门整合与专项验收
├── deliveries/             逐项生成来源、尺寸、哈希
└── references/             本地绘制参考图（不进入 Git 或发布包）
```

命名规则：

- 类型 ID 用三位数字；版本用 `vN` 后缀，修订必须新增版本，不覆盖已有像素。
- 单位图集按页拆分（`page-NN`），页与页之间不重叠。
- 武将头像按全局索引命名，不按姓名或排序位置。
- 地图分块文件名为块坐标与 LOD，清单记录每块的矩形与字节数。

## 4. 帧契约

每项素材记录：

| 字段 | 说明 |
|---|---|
| 稳定 ID | 类型/武将/地形组/地图 |
| 银行与帧 | 来源银行与帧号 |
| 调色板 | 采用的调色板 |
| 尺寸 | 像素宽高 |
| 透明边界 | alpha 非空包围盒 |
| 锚点 | 底边中心 |
| 原帧顺序 | 动画序列表 |
| 方向/阶段 | 8 方向、建造/损毁阶段 |
| 提示词 | 生成用提示词（交付记录） |
| 验收状态 | 用户验收/技术验收 |

约束：

- 动画使用序列表，不由图集列数推断。
- 人物按稳定索引对应原脸；姿态与朝向按序列表。
- 透明覆盖、内容框、世界尺寸、锚点与帧顺序分别记录。
- 缺失帧必须显式回退（当前为 0），回退来源写入清单。
- 阵营色只作用于原有阵营色区域；无阵营色的平民、云梯保持固定配色。

## 5. 动画

| 动作行 | 用途 |
|---|---|
| `walk` | 默认攻击/修理动作行；保留数据标签，移动时不使用 |
| `act1` / `act2` / `act3` | 采集、施工、攻击等动作 |
| `turn` | 行走步态、转身与待机姿势 |
| `die` | 阵亡 |

- 每个动作行按 8 方向存帧序号数组；精灵表从北起顺时针排列，屏幕角度从东起顺时针排列，表现层按 `(屏幕方向 + 2) & 7` 转换。移动使用步态行，即使正在追击也不播放攻击；站定执行攻击/修理后才使用动作相位。
- 建筑使用建造/损毁阶段帧，按 HP 比例选帧。
- 死亡动画每 0.08 秒推进一帧。
- 图标、头像、UI 不参与动画计时。

## 6. 地形

### 6.1 图层

| 层 | 内容 |
|---|---|
| 0 | 地形本体：水域、陆地、道路、驳岸 |
| 1 | 中层：崖壁、栅栏、树 |
| 2 | 顶层：近景遮挡物 |

- 层 0 单独渲染即为完整可读地形；层 1/2 的非空结构同时是通行阻挡。
- 地形组共 14 组（草地、土路、浅砾、水岸、石墙、城垛、红土、木栅栏等）。

### 6.2 装配

1. 按地图的行列与格位取地形组变体；
2. 按层序 0 → 1 → 2 叠加；
3. 用源几何掩码与边缘扩展消除透明接缝；
4. 生成 256×256 世界像素分块，纹理 4/2/1 三档；
5. 写入分块清单（矩形、LOD、字节数、预算）。

- 运行包只保留高清分块；源母版不入包。
- 事件地形补片（如桥梁被毁）在满足条件时叠加。
- 城门地形使用独立模块：门洞内裁切地形、门扇开闭与通行状态一致，门框采用薄接缝；城墙主体、砖块尺寸与等距方向沿用地图地形。

## 7. 阵营色

| 项 | 规则 |
|---|---|
| 来源 | 原始调色板中的阵营色区间 |
| 方式 | 声明 `teamTintable` 的母版按实际布料/面板区域换色 |
| 范围 | 仅阵营色区域；金属、肤色与固定配色不受影响 |
| 遮罩 | `team_palette.json` 记录图集与颜色映射 |
| 回退 | 非阵营素材不启用换色 |

## 8. UI 素材

| 项 | 规格 |
|---|---|
| HUD 底材 | 顶部通栏、左条、右面板、底栏四条；九宫格边框 |
| 红匾 | 「赤壁」匾额，透明通道，叠在木雕之上 |
| 资源图标 | 2×2 图集：金、粮、木、铁 |
| 命令图标 | 7×5 图集，按实测分隔线切格；单态图 + 运行时调制出按下/悬停 |
| 光标 | A 图集（10 状态 × 4 帧）、B 边缘箭头 8 帧、C 红旗 4 帧 |
| 装饰 | 龙纹横条、金色边框、木纹按钮底 |

- 图标切格使用实测分隔线，不假设等距网格。
- 动态数字、姓名、属性行与按钮文字由 UI 绘制，不烘焙进母版。
- 640×480 基准布局；1920×1080 与 1560×1440 均需验证。

## 9. 制作管线

### 9.1 超分

```
透明区颜色外扩（dilate）
  → realesrgan-ncnn-vulkan
      单位/建筑：realesrgan-x4plus-anime ×4
      地形整图：realesrgan-x4plus
  → 原图掩码合成 RGBA
```

- 工具：`tools/hd/hd_sample.mjs`、`tools/hd/hd_sprite.mjs`。
- 超分只负责尺寸放大；是否重绘以交付记录中的生成来源为准。
- 地形整图超分避免逐砖接缝；单位/建筑按图集超分。

### 9.2 渲染倍率

| 项 | 规则 |
|---|---|
| 世界坐标 | 保持 44 像素格距 |
| 精灵贴图 | ×4（绘制缩放 1/4） |
| 地形贴图 | ×2（绘制缩放 1/2） |
| 混合倍率 | 按表实际尺寸比写入 `sheetK`，支持 ×4/×2/1 |
| 显存门禁 | 最大地图全部渲染纹理峰值 < 768 MiB |
| 降档 | 超限的大表降为 ×2（下限 1× 不再降） |

### 9.3 合成注意

- 合成时若把 dilate 输出的 RGB 目录当作原图目录，会静默产出 3 通道 RGB，导入后成为黑底精灵。
- 合成前确认输入为 RGBA 原图；输出后检查 alpha 通道与包围盒。

## 10. 交付与清单

| 文件/目录 | 内容 |
|---|---|
| `godot/chibi_remake/art/full/manifest.json` | 运行素材总清单 |
| `godot/chibi_remake/art/production/*.json` | 素材契约、覆盖、提示词、交付记录 |
| `godot/chibi_remake/art/production/references/` | 本地绘制参考图（不进入 Git 或运行包） |
| `godot/chibi_remake/art/production/deliveries/` | 生成源、尺寸、哈希、提示词 |
| `tools/inputs/art.sha256` | 母版逐文件 SHA-256 与字节数 |

规则：

- 清单增量写入，保留已验收记录；拒绝用不同像素覆盖已有目标。
- 修订使用新版本路径；旧版本与交付记录保留。
- 激活已有交付需要显式步骤并记录验收状态。
- 源图与运行图分离：运行工程只引用 `art/full` 下的高清素材。

## 11. 素材保管

- `tools/inputs/runtime_assets.sha256` 声明运行和标准构建需要的素材、字节数、SHA-256 与必要导入配置；其中的二进制文件使用 Git LFS。清单 JSON、着色器源码及 UID 继续版本管理。
- `art/full/maps` 的烘焙整图、未被运行清单引用的生产母版、`art/production/references` 和 `research/*/assets` 参考素材仅本地保存，重新绘制和烘焙时才需要。Git 忽略不提供这些本地文件的版本历史。
- 备份示例：

```powershell
robocopy godot\chibi_remake\art\full D:\backup\chibi-art /MIR /R:1 /W:1
```

- 恢复后校验：

```powershell
node tools/art_manifest.mjs --check
node tools/art_manifest.mjs --check --hash
```

上面的全母版审计用于本地美术生产；从 Git 克隆后的日常检查使用 `node tools/runtime_assets.mjs --check`，无需恢复参考图或完整母版。

- 母版丢失不能用发布包反推，只能从备份恢复。

## 12. 验收

| 项 | 判据 |
|---|---|
| 覆盖 | 27 类建筑、26 个兵种定义、117 头像、14 组地形、34 张地图均有高清素材 |
| 回退 | 运行帧表显式回退为 0 |
| 透明 | alpha 边界与非空区域符合契约 |
| 帧序 | 动画按序列表播放，不缺帧、不串帧 |

| UI | 三种分辨率下布局正确，图标切格无错位 |
| 显存 | 最大地图渲染纹理峰值 < 768 MiB |
